## 규칙
- 등록: 기존 영웅 20종 중 최대 3종, 무료. 등록 때 이름(닉네임 검증 `checkName` 재사용: 2~10자, 한글·영문·숫자·공백·_.-, 금지어). 등록 후 이름 변경·해제 UI 없음(저장값 직접 삭제 외).
- 판 시작: 등록 영웅이 있으면 선택창(랜덤 / 내 영웅 N), 없으면 기존처럼 바로 시작. 마지막 선택 강조. 다시 하기는 같은 선택 유지(강화는 최신 저장값).
- 코인(`malang-myhero`.coins): `coinsFor = floor((max(0,R-9) + floor(kills/50) + 클리어30) x (1+0.05 x 보상단계))`. 연습은 절반, 프라이빗 시즌 판은 지급 없음. 봇 기준 R40 약 64, R45 약 74, 클리어 91+. (kills 가 봇 기준 R40 에 약 1700)
- 시장(영웅별 `up`): 비용 n단계째 `[60,100,160,240,340]`(누적 900), 영웅당 총합 10단계 상한.
  | 방향 | 최대 | 효과/단계 | 적용 |
  |---|---|---|---|
  | 공격 atk | 5 | 공격력 +3% | fx.atkMul -> game.js unitMul |
  | 보상 rew | 5 | 처치 보상 +4%, 코인 +5% | fx.killMul -> killMob, coinsFor |
  | 할인 disc | 3 | 공업 강화 비용 -4% | fx.upCost (기존 영웅값과 곱) |
  | 시작 자원 start | 5 | 시작 미네랄 +8 | fx.startMin 에 가산 |
- **시즌/규칙 판**: `rules` 가 있으면(프라이빗 시즌) 내 영웅 선택 UI 없음 + game.js/replay 모두 mine 무시(랜덤 영웅, 강화 없음). 공개 시즌(랭킹 도전, rules 없음)과 연습에서는 적용.
- 저장 키: `malang-myhero` {v,coins,heroes:[{id,name,up}]}, `malang-myhero-pick`. 로드 시 검증해 손상값은 걸러냄(기기 로컬이라 조작 가능성은 서버 캡 검증으로 방어).

## 서버 검증 조사 결론
- submit-score 는 **서버 시뮬 재생**이다: seed + 입력 로그(inputs)로 engine.js(data.js+game.js 번들)를 돌려 점수/라운드/클리어가 클라이언트 주장과 같아야 저장(`score_mismatch` 422). 영웅은 seed 에서 결정되므로 클라이언트가 임의 영웅/강화를 쓰면 **그대로는 항상 불일치로 거부**된다.
- 해결(구현함): 클라이언트가 `mine:{hero,up:{atk,rew,disc,start}}` + `hero_name` 을 함께 보내고, 서버가 같은 `validateMine`(단계 범위·총합 10 상한)을 통과시킨 뒤 같은 `applyMine` 으로 재생한다. 강화 수치를 서버가 믿는 게 아니라 **상한 안의 어떤 조합이든 재생으로 점수를 재현**하므로 조작 점수는 불가(강화를 지어내도 그 강화로 재생된 점수만 인정). 한계: 서버는 그 강화를 실제로 샀는지(코인)는 알 수 없다 -> 모든 플레이어가 상한 조합(예: 공격5+보상5)을 공짜로 쓰는 패치 클라이언트가 가능. 완화안: (a) 현 상태 수용(영웅당 +15%/+20% 수준이라 영향 제한), (b) 랭킹을 강화 판 별도 보드로 분리(결정 필요), (c) 서버에 코인 원장 도입(로그인/계정 필요, 규모 큼).
- 이름 저장: DB 에 `scores.hero_name` 필요 -> `supabase/migrations/007_hero_name.sql`(컬럼 + 뷰 3개 갱신 + `score_set_hero_name` rpc, service_role 전용). index.ts 가 재생 일치 후 저장 성공 시에만 rpc 호출(실패해도 점수 유지). 이름은 서버가 `checkName`+BAD_WORDS 로 재검증.
- 하위 호환: 클라이언트는 `CONFIG.MYHERO_RANKED`(기본 false)가 true 일 때만 mine 을 보내고 hero_name 조회를 시도하며, 007 이 없어 조회가 실패하면 hero_name 없이 재조회한다. 구 서버에 보내면 불일치로 거부되므로 false 일 때 내 영웅 판은 랭킹에 전송하지 않는다("준비 중" 안내, 코인은 지급). GAME_VER 는 4 유지(랜덤 판 로직 불변).
- 변경 파일(서버): supabase/functions/submit-score/{index.ts, replay.js, engine.js(`node tools/build_engine.js` 재생성)}, tools/build_engine.js(MYHERO 구간 추출·start(seed,rules,mine)).

## 배포 순서 (사용자 승인 후)
1. `007_hero_name.sql` 을 SQL Editor 에서 실행. 2. `supabase functions deploy submit-score --no-verify-jwt`. 3. config.js `MYHERO_RANKED:true` + 클라이언트 배포(sw CACHE_VERSION 은 이미 v19-myhero). 이 순서를 지키면 어느 단계에서도 기존 기능이 깨지지 않는다. 배포 후 스모크: 내 영웅으로 한 판 -> 랭킹에 `🦸이름` 표시 확인.

## 사용자 결정 필요
1. 강화 영웅과 랜덤 영웅을 한 보드에서 경쟁시키는 것(+15~20% 이점)이 괜찮은지 / 위 (a)(b)(c) 중 선택.
2. 코인 수치·비용표(봇 기준 설계, 실제 플레이로 조정 필요).
3. 이름 변경/영웅 해제(강화 소실) UI 추가 여부. 현재는 변경 불가.
4. 프라이빗 시즌에서 내 영웅 허용 여부(현재 불허, 서버 private.ts 는 mine 미전달).
5. 랭킹 "내 기록" 탭(profile rpc)에는 hero_name 미표시(rpc 수정 필요 시 008).
