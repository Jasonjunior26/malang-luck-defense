# 친구 서버 배포

순서: DB(마이그레이션) -> 함수 -> 클라이언트.

1. 선행: 002, 003 적용됨(`players.user_id` 필요). 004 와는 독립.
2. DB: Supabase SQL Editor 에 `supabase/migrations/005_friends.sql` 전체를 붙여넣고 Run (재실행 안전).
   - 기존 players 에 4자 `friend_code` 가 백필되고, 새 players 는 트리거가 자동 부여한다.
   - 확인: `select count(*) from players where friend_code is null;` -> 0, `select count(*) from friendships;` -> 0.
3. 함수: `node tools/test_friends.mjs && node tools/test_private.mjs && node tools/test_function.mjs` 통과 확인 -> `supabase functions deploy submit-score --no-verify-jwt`.
4. 클라이언트 배포는 함수 이후.
5. 동작 확인(JWT 필요, 카카오 연결된 계정): body `{"action":"frMyCode"}` -> `{"ok":true,"name":"..","code":"AB3K","tag":"..#AB3K"}`.

## 운영 메모
- 액션: frRequest frAccept frDecline frRemove frBlock frList frBoard frMyCode (JWT 필수, device_id 불필요).
- 친구 가능 조건: 카카오 계정에 연결된 player (게스트는 코드가 있어도 요청 대상/주체가 될 수 없음).
- 한도: 친구 100명, 보낸 대기 요청 30개. 레이트 리밋 kind: `friend`(쓰기 12/분/계정), `friend_read`(읽기 30/분).
- 코드 충돌/오남용 시: `update players set friend_code = friend_code_gen() where device_id = '...';` 로 재발급(기존 링크는 무효화됨).
- 연락처(전화번호 등)는 수집·저장하지 않는다.

## 롤백
- 함수: 이전 커밋으로 되돌려 재배포 (fr* 가 없어도 기존 액션은 영향 없음).
- DB(친구 데이터 삭제 주의):
  ```sql
  drop table if exists public.friendships;
  drop trigger if exists players_friend_code_trg on public.players;
  drop function if exists public.friend_board(uuid, int), public.friend_list(uuid), public.friend_block(uuid, text), public.friend_remove(uuid, text),
    public.friend_decline(uuid, text), public.friend_accept(uuid, text), public.friend_request(uuid, text), public.friend_my_code(uuid),
    public.fr_count(uuid, text), public.fr_target(text), public.players_set_friend_code(), public.friend_code_gen();
  drop index if exists public.players_friend_code_uq;
  alter table public.players drop column if exists friend_code;
  ```
