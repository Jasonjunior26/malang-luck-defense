## 확정 결함

### F1. [중요] 유예 판정이 첫 시즌 경계(cur=3)에서만 동작한다. 시즌 4부터는 종료 직후 10분 안에 들어온 사용자의 보상 팝업이 한 주 밀린다 (rewards.js:230)
- 근거: 서버(012:26-30, 114-115)에서 `last.season = reward_settled_upto()` 이다. 유예 중에는 이 값이 `cur - 2` 이다. 시즌 4가 시작된 직후 10분 동안 서버는 `cur:4, last:{season:2}` 를 돌려준다. 이때 last 는 null 이 아니다.
- 그런데 클라의 유예 조건은 `pre = m.cur >= 3 && !m.last && !m.pending.length` 이다. 이 조건은 last 가 null 인 경우(cur=3 의 첫 경계)만 잡는다.
- 결과: 시즌 2 팝업을 이미 본 사용자(seen=2)는 `needShow=false` 가 된다. 이어서 `done()` 이 `CALL_KEY=4` 를 기록한다. 그 뒤 시즌 4 동안에는 boot 가 매번 "done" 을 돌려줘 서버를 부르지 않는다. 그래서 시즌 3 보상 팝업과 1~3위가 그 주 내내 뜨지 않는다.
- 다음 주(cur=5)에는 pending 에 시즌 3·4 가 함께 와서 지급된다. 코인 손실은 없다. 다만 시즌 3 의 1~3위 화면은 끝내 보이지 않는다.
- pending 이 있어 받기를 눌러도 같은 일이 생긴다. ack 성공 뒤 `done()` 이 `CALL_KEY=cur` 를 기록하기 때문이다.
- 테스트 공백: tools/test_rewards_ui.mjs:274 의 G 는 cur=3·last:null 만 검사한다.
- 수정안:
  ```js
  const pre = m.cur >= 3 && (!m.last || m.last.season < m.cur - 1);
  ```
  - 유예 중에는 last 가 `cur-2` 이므로 이 조건으로 잡힌다.
  - pending 이 있으면 5분 뒤 다시 확인해도 무방하다. 지금처럼 `return "grace"` 해도 된다.
  - G 에 `cur:4, last:{season:2}, pending:[]` 사례를 추가한다.

### F2. [사소] 큐에서 꺼낸 보상 팝업이 열리지 않고 return 하면, closeModal 이 남은 큐와 일시정지 해제를 건너뛴다 (rewards.js:238, ui.js:389-391)
- `closeModal` 은 `nx()` 다음에 곧바로 return 한다. 그래서 `go` 가 아무것도 열지 않으면 그 뒤 큐 항목이 실행되지 않고, `S.paused=false` 도 실행되지 않는다.
- 지금은 판을 시작하는 모든 경로(startRun 1331, myhero.js:183, restartGame 1239, seasons.js:368 hideModal)가 보상 항목을 먼저 지운다. 그래서 이 상태에 도달하는 경로를 찾지 못했다.
- 방어 수정: TITLE_ON=false 로 return 하기 전에 `const nx = MODAL_Q.shift(); if (nx) nx();` 를 넣는다.
