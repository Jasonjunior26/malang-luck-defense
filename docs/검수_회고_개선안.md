# 검수 회고와 개선안 (2026-10-30 배포 건)

## 요약
1. 하루 동안 "완료" 보고를 받아 배포했지만, 폰 화면을 본 사람은 사용자뿐이었다. 결함 9건이 사용자 확인에서야 드러났다.
2. 기존 테스트(`tools/test_*.mjs` 8개)는 서버 핸들러, 리플레이 점수 일치, 규칙 엔진, 시즌 UI의 순수 로직만 본다. 레이아웃, 모달과 일시정지의 상태 전이, 요구사항 일치는 검증 범위 밖이다.
3. 원인은 "눈으로 확인하는 단계 부재", "원문 요구 체크리스트 부재", "증거 없이 완료 수용" 세 가지다. 개선은 배포 후 자동 스모크, 요구 체크리스트와 증거 첨부, 독립 검수로 한다.

## 원인 분석
테스트 범위는 `tools/` 파일 헤더에서 확인한 사실이다. "에이전트 환경에서 localhost가 막혀 브라우저 렌더를 못 봤다"는 지시문에서 받은 정보로, 코드로는 확인하지 않았다.

| # | 문제 | 왜 못 걸렀나 |
|---|---|---|
| 1 | [랭킹]을 눌렀는데 게임 시작 | 클릭 흐름은 어떤 테스트도 다루지 않는다(DOM을 쓰는 테스트가 없다). 재현하지 못한 채 가드만 넣고 종결했다. 원인을 확정하지 않았고 계측도 없었다. |
| 2 | 몬스터가 안 나옴 / 랭킹을 눌러야 진행 | `test_replay`, `test_rules`는 `HEADLESS=false`에 렌더 스텁으로 봇이 한 판을 돈다. 즉 `S.paused`를 직접 풀고 진행한다. 실제 UI의 `modal()` / `closeModal()` / `confirm`이 `S.paused`를 바꾸는 경로(`ui.js` 359~372행의 MODAL_ON, CONFIRM_ON, prev 복원)는 테스트에 없다. #1과 같은 뿌리일 가능성이 높다(추측). |
| 3 | HUD 칩 높이 들쭉날쭉 | 실제 렌더 측정이 없다. CSS를 고친 뒤 값을 측정하지 않고 "고쳤다"를 수용했다(2회 반복). 칩 `.chip`에는 `index.html`의 두 군데(26행, 30행)에 서로 덮어쓰는 규칙이 있어, CSS만 읽어서는 결과를 알 수 없다. |
| 4 | 게임 중 홈/랭킹 버튼 없음 | 사용자 원문 요구를 번호 목록으로 보관하지 않았다. 구현 에이전트의 해석에서 누락됐고, 배포 때 원문과 대조하지 않았다. |
| 5 | 히어로가 랜덤이 아닌 데일리 | 요구("모든 판 랜덤")와 구현의 대조 부재. 로직 테스트는 "서버와 클라 결과 일치"만 보므로 시드 정책이 요구와 맞는지는 검증하지 못한다. |
| 6 | 몬스터 수 숫자가 박스를 넘침 | "UX 전수조사"가 코드 읽기 기반이었다(추측). 큰 숫자, 좁은 폭 같은 경계값을 실제로 렌더해 보지 않았다. 8b6c3a4에서 뒤늦게 수정했다. |
| 7 | 홈 확인 모달 두 버튼이 모두 취소처럼 동작 | 모달 동작 테스트가 없다. `confirm` 모달(`cno`/`cok`) 버튼을 눌러 보는 절차가 없었다. |
| 8 | 히어로 설명 문구 장황 | 문구 품질 기준이 없고 사용자 시점 리뷰도 없었다. 에이전트는 자기 설계 메모를 문구로 옮겼다(추측). |
| 9 | 전체화면에서 주소창이 보임 | PWA, 전체화면은 실기기(iOS/안드로이드 브라우저)에서만 확인된다. 데스크톱 에이전트가 검증할 수 없는 항목을 "보정 완료"로 보고했다. 불확실하다고 표시하지 않았다. |

공통 원인
- 완료 기준이 "코드를 바꿨다 + 기존 테스트 통과"였다. 증거(스크린샷, 측정값, 로그)를 요구하지 않았다.
- 작성자 에이전트가 곧 검수자였다.
- 배포 직후 공개 URL을 연 스모크가 없었다. 빌드 관련 문서 `진행현황_다음할일.md`도 "완료·배포됨"만 적고 검증 방법은 적지 않았다.

## 개선안
| 안 | 내용 | 비용 / 효과 |
|---|---|---|
| A | 배포 후 공개 URL을 claude-in-chrome로 열어 `docs/배포후_스모크체크.md`의 스니펫 실행(몬스터 등장, `S.tick` 증가, 칩 높이, 홈/랭킹/모달 후 정상) | 비용 낮음(5분, 스니펫 붙여넣기) / 효과 높음: #1 #2 #3 #6 #7을 배포 직후 잡는다. |
| B | 사용자 원문 요구를 번호 체크리스트(`docs/요구_체크리스트.md`)로 만들고, 항목마다 증거(측정값, 스크린샷, 테스트명)를 달아야 "완료"로 인정 | 비용 낮음(문서 1개) / 효과 높음: #4 #5 #8 같은 요구 누락과 불일치 차단. |
| C | 상태 전이 회귀 테스트: `ui.js`의 modal/confirm/pause 규칙을 순수 함수(`nextPaused(state, event)`)로 분리하거나, 최소 DOM 스텁(`$`, classList)을 vm에 넣어 `modal -> closeModal -> S.paused===false`, `confirm cno/cok` 시퀀스를 검증 | 비용 중간(분리 리팩터 약 반나절) / 효과 중간-높음: #1 #2 #7 재발 방지. 단 ui.js는 현재 다른 작업 중이므로 작업 종료 후 진행. |
| D | 재현 불가 버그는 가드로 종결하지 않는다. `console.warn` 계측(예: 모달 오픈/클로즈 시 `S.paused`, `TITLE_ON`, 클릭 대상 id)을 넣어 원인 확정 후 종결. 확정 전에는 "미해결(가드 임시)"로 기록 | 비용 낮음 / 효과 중간: 같은 버그의 재발 시 원인을 즉시 볼 수 있다. |
| E | 배포 전 독립 검수 에이전트(작성자와 다름)에 요구 체크리스트(B)와 diff만 주고 대조시킨다. 작성자의 해석은 주지 않는다 | 비용 중간(에이전트 1회) / 효과 높음: #4 #5 #8 류의 누락 포착. |
| F | 폰 확인 최소 목록(아래 5개)을 배포 보고 끝에 붙여 사용자가 1분에 확인 | 비용 매우 낮음 / 효과 중간: 실기기 항목(#9)은 사람이 보는 것이 가장 확실하다. |
| G | 실기기 전용 항목(전체화면, 주소창, 안전영역)은 에이전트가 "확인 불가"로 표시하고 완료로 세지 않는다 | 비용 없음 / 효과 중간: 과신 보고 방지. |

폰 확인 5개 (F)
1. 타이틀에서 [랭킹]을 누르면 랭킹만 열리고 게임은 시작되지 않는다.
2. [시작] 후 3초 안에 몬스터가 나오고 라운드가 진행된다.
3. 상단 칩 4개의 높이가 같고 숫자가 박스를 넘지 않는다.
4. 게임 중 홈 버튼, 랭킹 버튼이 동작하고, 모달을 닫은 뒤 게임이 계속된다.
5. 홈앱(홈 화면에 추가) 실행 시 주소창이 없다. 브라우저에서는 주소창 숨김이 안 될 수 있다.

## 다음 배포부터 적용할 체크리스트
1. 사용자 요청 원문을 번호 목록으로 `docs/요구_체크리스트.md`에 옮긴다.
2. 항목마다 증거(측정값, 스크린샷, 테스트명) 없이는 "완료"로 표시하지 않는다.
3. 기존 `node tools/test_*.mjs` 전부 통과를 확인한다.
4. 작성자와 다른 에이전트가 체크리스트와 diff를 대조한다.
5. 배포 후 공개 URL에서 `배포후_스모크체크.md` 스니펫 4개를 실행하고 결과를 보고에 붙인다.
6. 재현 불가 버그는 계측 로그를 넣고 "미해결"로 남긴다. 가드만으로 종결하지 않는다.
7. UI 변경은 큰 숫자, 긴 문자열, 좁은 폭(360px)에서 렌더 측정한다.
8. 실기기 전용 항목은 "확인 불가"로 명시한다.
9. 사용자용 폰 확인 5개를 보고 끝에 붙인다.
10. `진행현황_다음할일.md`에 검증 방법과 결과를 같이 적는다.
