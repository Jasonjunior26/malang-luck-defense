# 이용 행동 지표 설계 (2026-11-12, 설계만 — 코드·DB·배포 변경 없음)

범위: "게임을 켠 뒤 사람들이 실제로 무엇을 하는가"(체류시간, 화면·버튼 사용, 이탈)를 수집·집계해 운영 대시보드 '이용 행동' 탭에 넣는 설계.
이 문서는 사용자 승인 전 초안이다. `docs/진행현황_다음할일.md` 는 건드리지 않았다. 배포 순서는 CLAUDE.md 규칙(마이그레이션 → 함수 → 클라이언트 → 플래그)을 따른다.

## 0. 확인한 사실과 설계 가정

**코드에서 확인한 것**
- 분석 이벤트·페이지뷰·체류시간 수집은 없다. 클라이언트→서버 통로는 `ui.js` `api(action, body)`(732줄) 하나이고 대상은 Edge Function `submit-score` 하나다. 이 함수의 허용 action 은 `index.ts` 80~87줄(`submit/register/rename/profile/import/me/link` + `ps*` + `fr*`).
- 서버 DB 는 RLS 켜고 정책 없음(service_role 만). 속도 제한은 DB RPC `rate_limit_hit(ip_hash, device, ip_max, dev_max, kind)`(002 마이그레이션 68줄, `submit_log` 사용).
- `api()` 는 `Content-Type: application/json` 으로 호출한다. 그래서 브라우저가 CORS 사전 요청(OPTIONS)을 먼저 보내고, 함수가 OPTIONS 에 204 를 직접 응답한다(`index.ts` 67줄). **OPTIONS 가 함수 호출 수에 잡히는지는 확인하지 못했다**(`functions.json` 은 일 총량만 있음).
- 오프라인 대기열(`QUEUE_KEY`, 최대 20건)은 점수 제출 전용이다. `visibilitychange` 훅(ui.js 59줄)은 오디오 정지용이며 서버 전송과 무관하다. `pagehide`/`beforeunload` 는 없다.
- **친구 기능은 클라이언트 화면이 없다**(`docs/소셜_현황.md` 13줄: `ui.js`·`seasons.js` 에 `fr*` 호출 없음). 카카오 로그인은 `KAKAO_ENABLED:false`. 따라서 친구·로그인 후 행동은 지금은 측정 대상이 아니다.
- 광고 시청 코드는 없다(`docs/광고수익_세금_검토.md` 는 검토 문서뿐).
- 규모: `kpi.json` players_total 30, active_7d 13, active_30d 15. `daily.json` 최근 일 활성 2~9명. `functions.json` 일 함수 호출 111(11-08)·440(11-07)건(그날 활성 9·6명, 개발자 스모크 포함 가능성이 있어 1인당 값은 부정확).

**설계 가정 (실측 아님, 사용자 확인 필요)**
- G1. DAU 1인당 하루 세션 1.5회, 세션당 이벤트 25개, 세션당 전송 3회(배치). 실제 값은 1~2주 수집 후 보정한다.
- G2. 이벤트 1건 저장 크기 200바이트(행 + 인덱스 포함 추정), 세션 요약 1행 300바이트. 실측하지 않았다.
- G3. 무료 플랜 한도는 사용자가 알려준 값을 그대로 쓴다: 함수 호출 월 50만, DB 500MB, 송신 5GB. 공식 문서로 재확인하지 않았다.
- G4. 기기 식별은 기존 `device_id`(localStorage `malang-device`) 기반이다. 로그인 전이라 "사람"이 아니라 "기기"다.

## 2. 수집 방식

### 2.1 세션 정의
- `sid`: 클라이언트가 만드는 무작위 12자(영숫자). `deviceId()` 와 별개이며 닉네임·점수와 연결되지 않는다.
- 저장: localStorage `malang-ses` = `{sid, last_active(ms), n}`. 읽기·쓰기 모두 try/catch(기존 `lsGet/lsSet` 사용).
- 새 세션 조건: 앱 시작 시 또는 숨김→보임 복귀 시 `now - last_active > 30분` 이면 새 `sid`. 아니면 같은 세션을 잇는다.
- `last_active` 갱신: 숨김 전환 시점, 그리고 `pointerdown`(ui.js 57줄에 이미 전역 리스너가 있어 거기에 얹는다) 시 10초에 한 번만 기록(쓰기 빈도 제한).
- 한계: 앱이 강제 종료돼 `hidden` 이 발생하지 않으면 마지막 구간이 빠진다(과소 추정). 다음 실행 때 localStorage 에 남은 누적값을 `rec:1` 로 한 번 보낸다.

### 2.2 체류시간 계산 (하트비트 없음)
세 개의 누적 타이머를 쓰고 setInterval 은 쓰지 않는다. 상태가 바뀔 때(화면 전환, 판 시작/종료, 숨김/보임)만 `Date.now()` 차이를 더한다.

| 값 | 정의 | 누적 조건 |
|---|---|---|
| `vis_s` | 보이는 시간 | `document.hidden === false` 인 동안 |
| `play_s` | 게임 중 시간 | 보이는 동안 + `!TITLE_ON`(판 시작~결과 화면 이전). 결과 모달 이후는 제외 |
| `act_s` | 상호작용 시간 | 입력 사이 간격을 최대 30초로 잘라 합산(방치 보정) |

- 모달로 `S.paused` 인 시간은 1차에서 `play_s` 에 포함한다(앱을 보고 있는 시간). 빼려면 `modal()`/`closeModal()`(ui.js 383·385줄) 두 곳 훅이 필요하다.
- 전송 값은 **세션 누적값(cumulative)** 이다. `hd` 이벤트마다 최신 누적을 보내고 서버는 같은 `sid` 의 최댓값만 취한다. 중복·재시도·순서 뒤바뀜에 안전하다.
- `act_s` 한계: 방어 게임은 입력 없이도 진행되므로(코드의 `_lastInput` 도 BGM 절전용) `act_s` 는 "손을 댄 시간"일 뿐 몰입 시간이 아니다. 대시보드 주 지표는 `vis_s`·`play_s`.

### 2.3 이벤트 스키마
공통 필드는 요청 본문에 한 번만 담고 이벤트에는 넣지 않는다.

```
POST submit-score  (Content-Type: text/plain;charset=UTF-8, 본문은 JSON 문자열)
{ "action":"ev", "device_id":"<uuid>", "sid":"a1b2c3d4e5f6", "ver":"9",
  "env":{"pf":"ios|android|desktop|other","sa":0|1,"vw":"s|m|l","new":0|1},
  "ev":[ {"t":<ms 오프셋>,"e":"scr","s":"ranks_season"}, ... ] }
```
- `t` 는 세션 시작 대비 오프셋(ms 정수). 절대 시각은 서버 수신 시각을 쓴다(클라이언트 시계 불신).
- `pf`: UA 에서 coarse 3분류만(원문 저장 금지). `vw`: 가로 360 미만/430 미만/이상. `new`: 이 기기의 첫 세션 여부.
- 이벤트 이름 사전(전부 enum, 서버가 화이트리스트로 검사하고 모르는 값은 버린다):

| e | 속성(허용 키만) | 뜻 |
|---|---|---|
| `ss` | `src`(launch\|resume) | 세션 시작 |
| `scr` | `s`(화면 enum §3.1) | 화면·모달 열림 |
| `tap` | `b`(버튼 enum §3.2) | 화면 전환이 없는 버튼(소리, 절전, 배속, 메뉴 등) |
| `rs` | `lg`(rand\|mine\|ps), `h`(영웅 id 10종 enum) | 판 시작 |
| `re` | `lg`, `r`(라운드 0~60), `w`(0\|1), `sc`(점수 정수), `dur`(초, 보이는 시간), `n`(행동 횟수 객체: draw·merge·sell·up·rng·ticket·lock·auto·spd), `ex`(end\|home\|bg) | 판 종료(결과 화면 또는 중간 이탈) |
| `hd` | `vis`,`play`,`act`(세션 누적 초), `last`(마지막 화면 enum), `rec`(0\|1) | 숨김·복구 시 스냅샷 |

- 속성 규칙: 값은 enum·정수·0/1 만. **닉네임, 영웅 이름(`heroName`), 초대 코드, 시즌 이름, 입력창 텍스트, URL, UA 원문은 넣지 않는다.**
- 크기 상한: 이벤트 1건 JSON 120바이트 이하(서버가 초과분 폐기), 요청당 이벤트 30개 이하, 본문 4KB 이하(함수 전체 상한 `MAX_BODY` 300KB 와 별개로 `ev` 만 더 조임).

### 2.4 배치 전송
- 메모리 큐에 쌓는다(localStorage 에 이벤트 원본을 쌓지 않는다: 쓰기 부하·용량).
- 전송 조건(먼저 오는 것): ① 큐 20건 ② `re` 이벤트 직후 200ms 뒤(판 종료마다 1회. 점수 제출과 같은 시점이라 합치지 않고 시간차를 둔다) ③ 숨김 전환(`visibilitychange` hidden, `pagehide`) ④ 마지막 이벤트 후 90초(`setTimeout` 하나, 큐가 비면 해제).
- 숨김 때는 `navigator.sendBeacon(url, new Blob([json], {type:"text/plain"}))`. 미지원이거나 false 면 `fetch(..., {keepalive:true})`. **`text/plain` 을 쓰는 이유**: JSON 타입이면 사전 요청이 필요해 sendBeacon·keepalive 가 불안정하고 사전 요청이 호출 수에 잡힐 수 있다. 서버는 이미 `req.text()` 후 `JSON.parse` 하므로(index.ts 71~74줄) 읽는 쪽 변경이 없다. 단 `Content-Type` 이 달라도 CORS 헤더(`ALLOW_ORIGIN`)는 응답에 그대로 붙는다.
- 실패 시: 폐기가 기본이다. `hd` 는 누적값이라 다음 전송에 최신값이 다시 실리므로 재시도가 필요 없다. 오프라인 저장 없음(점수 대기열 `QUEUE_KEY` 와 섞지 않는다).
- 응답은 기다리지 않고 결과도 무시한다(게임·점수 제출에 영향 0). 서버가 429 를 주면 그 세션의 이후 전송을 중단한다.

### 2.5 샘플링 옵션
- 기본은 전수(현재 규모). 호출 수가 한도의 30%를 넘기면 켠다.
- 방식: `device_id` 해시 앞 2자리 16진수 값 < `CONFIG.EV_SAMPLE`(0~256) 인 기기만 전송. **세션 단위가 아니라 기기 단위**로 자르므로 퍼널·재방문이 깨지지 않는다. 비율은 `env` 에 실어 대시보드에서 배율 보정한다.
- 판수·점수·가입 수 같은 전수 지표는 샘플링과 무관하게 `scores`/`players` 에서 따로 센다.

### 2.6 서버 측 (action `"ev"` 신설)
`index.ts` 에서 `ps*`/`fr*` 분기(80~81줄)처럼 **`ev` 를 별도 핸들러(`events.ts`)로 분기**한다. 점수 재생 경로와 섞지 않는다.
1. `ev` 는 `device_id` 형식 검사 후, 점수 경로 앞에서 분기한다.
2. 본문 4KB·이벤트 30개·키/enum 화이트리스트 검사. 위반 이벤트만 폐기(전체 400 은 형식 오류일 때만).
3. 속도 제한: 기존 `rate_limit_hit` 에 새 kind `"ev"`(예: ip 60/분, 기기 12/분)를 추가한다. 추가 RPC 1회가 붙는다. 대안은 함수 인스턴스 메모리 카운터(콜드스타트 시 초기화되는 느슨한 제한, DB 왕복 없음). **결정 필요(§6)**.
4. 응답은 `{ok:true}` 로 최소화(송신량 절약).
5. 저장: `ev_ingest(p_dev, p_sid, p_ver, p_env jsonb, p_events jsonb)` RPC 1회로 배열 insert + 세션 행 upsert. service_role 전용(002 마이그레이션 패턴과 동일).
6. 기기 식별: 함수가 `sha256(EV_SALT + device_id)` 앞 16자를 `dev` 로 저장한다(기존 `IP_SALT` 해시 방식과 동일 패턴). `players`·`scores` 와 직접 조인되지 않는다. **사용자 결정 필요**: 원 `device_id` 를 쓰면 등록 여부·누적 판수와 교차 분석이 쉬워지지만 개인정보 최소 원칙과 멀어진다(권장은 해시).

### 2.7 테이블 설계 (마이그레이션 012 초안)
```sql
-- 원본(짧은 보존)
create table ev_raw (
  id bigint generated always as identity primary key,
  at timestamptz not null default now(),       -- 서버 수신 시각
  day date not null,                           -- KST 날짜(삽입 시 계산)
  dev text not null,                           -- sha256 앞 16자
  sid text not null, ver text not null,
  e text not null, s text, b text, lg text, hero text, ex text,
  t_ms int, r int, w smallint, sc int, dur int, n jsonb
);
create index on ev_raw (day, e);
create index on ev_raw (dev, sid);
-- 세션 요약(1행/세션, 90일 보존): 체류시간·마지막 화면
create table ev_session (
  sid text primary key, dev text not null, day date not null, started_at timestamptz not null,
  ver text, pf text, sa smallint, vw text, is_new smallint,
  vis_s int default 0, play_s int default 0, act_s int default 0, last_scr text,
  runs int default 0, runs_done int default 0, screens jsonb default '{}'::jsonb, -- {"ranks_season":2,...}
  ended_clean smallint default 0
);
create index on ev_session (day);
-- 일별 집계(영구, 작음)
create table ev_daily (
  day date, ver text, e text, key text,        -- key = scr.s / tap.b / lg 등
  cnt int, devs int, primary key (day, ver, e, key)
);
-- RLS 켜고 정책 없음. ev_ingest / ev_rollup(day) / ev_prune() 은 service_role 전용
```
- `ev_ingest` 가 `hd`·`scr`·`rs`·`re` 마다 `ev_session` 을 갱신한다(`vis_s = greatest(old, new)`).
- `ev_rollup(day)`: `ev_raw` → `ev_daily`(해당 날짜 delete 후 insert 로 재실행 안전).
- `ev_prune()`: **롤업이 끝난 날짜만** `ev_raw` 에서 삭제(보존 14일). 롤업 못 한 날의 원본은 지우지 않는다. `ev_session` 90일.
- 롤업 실행: `tools/dashboard_sync.mjs` 가 읽기 전에 `select ev_rollup(...)` 를 호출한다(동기화가 수동이라 며칠 걸러도 원본 14일 안에서 따라잡음). `pg_cron` 사용 가능 여부는 확인하지 못했다(없어도 동작하게 설계).

### 2.8 용량·호출 수 추정 (가정 G1·G2·G3)
산식: 이벤트/일 = DAU × 1.5 × 25, 호출/일 = DAU × 1.5 × 3(월 30일), 원본 보존 14일, 세션 요약 90일.

| DAU | 이벤트 호출/월 (한도 50만 대비) | 원본 행(14일) → 용량 (500MB 대비) | `ev_session` 90일 | 샘플링 시 |
|---|---|---|---|---|
| 100 | 13,500 (2.7%) | 52,500행 → 10.5MB (2.1%) | 4MB | 불필요 |
| 1,000 | 135,000 (27%) | 525,000행 → 105MB (21%) | 40MB | 50%: 호출 67,500(13.5%), 원본 52MB |
| 10,000 | 1,350,000 (270%, 초과) | 5,250,000행 → 1.05GB (210%, 초과) | 405MB | 10%: 호출 135,000(27%), 원본 105MB, 세션 40MB |

- **기존 호출량이 먼저 한도를 쓴다.** 현재 일 호출은 활성 1인당 약 12~73회(111÷9, 440÷6; 후자는 스모크 포함 가능). 1,000 DAU 면 기존만 월 36만~220만 회라, 이벤트 월 13.5만 회는 거기에 +6%~+37% 가 얹히는 크기다. **1,000 DAU 이상은 기존 호출 구조(사전 요청, 랭킹 조회 등) 점검이 이벤트 설계보다 먼저**다(이번 범위 밖. OPTIONS 집계 여부부터 확인).
- 송신(egress): 응답 `{ok:true}` + 헤더 약 300바이트로 가정하면 10,000 DAU 전수에서도 월 약 0.4GB(5GB 의 8%). 수신 본문은 송신 한도에 포함되지 않는 것으로 알고 있으나 확인하지 못했다.
- 현재 DAU(2~9)에서는 하루 호출 약 15~40회, 원본 월 1,000~3,000행 수준으로 무시할 만하다.

### 5.1 `tools/dashboard_sync.mjs` 추가분
`Q` 객체에 키-SQL 을 넣으면 `dashboard_data/out/<키>.json` 이 생기는 구조다(`run()`·`writeFileSync`, 87~91줄). 같은 패턴으로 추가하고, 시작 직후 `select ev_rollup(current_date - 1)`(실패해도 계속) 호출을 한 번 넣는다. 아래는 초안(`…` 는 같은 패턴 반복)이며 실행 검증은 하지 않았다.

### 5.2 '이용 행동' 탭 구성안 (KR Sales ERP 디자인: 막대·선·누적막대·히트맵, 도넛 금지)
1. 상단 KPI 타일 4개: 오늘 세션 수, 세션당 평균 보이는 시간, 첫 판 도달률(30일), 재방문율 D1. 숫자 + 7일 스파크라인(선).
2. 퍼널: 가로 막대 7단 + 단계 전환율(%) 라벨. 신규 기기만 보기 필터.
3. 체류시간 분포: 세로 막대(6구간) + 중앙값 표기. 옆에 일별 평균 체류 선 차트(90일).
4. 메뉴 사용: 가로 막대(화면·버튼별 사용 기기 수). 랭킹 탭 전환은 누적 막대(순위/승점/내 기록 × 운빨/내 영웅).
5. 판 행동: 이탈 라운드 막대(5라운드 구간), 판 종료 방식 누적 막대, 판당 행동 횟수 막대.
6. 이탈 지점: 마지막 화면 가로 막대 + 바로 이탈 세션 비율.
7. 시간대: 요일×시간 히트맵(KST), 시간대별 세션 막대.
8. 비교: 신규 vs 재방문, GAME_VER 별 체류·판수 그룹 막대. 표본이 작아 기기 수(n)를 항상 병기하고 n<20 은 회색 처리.

현재 활성이 2~9명이므로 비율 차트에는 기기 수 원값을 같이 보여준다.

## 결정 기록 (2026-11-12, 사용자가 선택을 위임함)
설계 선택만 확정한다. 마이그레이션 012, 함수 배포, 클라이언트 푸시, 플래그 켜기는 단계마다 사용자 승인 후 진행한다.

1. 기기 식별: 원 `device_id` 가 아니라 해시(서버에서 솔트 + SHA-256 앞 16자)로 저장한다. 점수·계정 테이블과 조인하지 못하게 분리해 개인정보 위험을 줄인다.
2. 고지·옵트아웃: 설정 메뉴에 '이용 기록 보내기' 켜기/끄기 한 줄을 둔다. 기본값은 켬, 끄면 이벤트를 만들지 않는다. 내용은 화면 이름·시간·판수뿐이고 닉네임·입력 텍스트는 보내지 않는다고 적는다. 법적 검토는 별도로 필요하다.
3. 속도 제한: 점수 경로와 섞지 않고 함수 메모리(기기 해시당 분당 상한)로 먼저 한다. DB RPC 호출을 늘리지 않기 위해서다.
4. 보존: 원본 이벤트 14일, 세션 요약 90일, 일별 롤업은 무기한.
5. 샘플링: 기본 100%. 일 활성이 3,000을 넘기 전에 플래그로 낮출 수 있게 서버 설정값으로 둔다.
6. 순서: 마이그레이션 012 → 함수 `ev` 액션 → 클라이언트 → 플래그. 대시보드 '이용 행동' 탭은 데이터가 쌓이기 전에는 '수집 전' 상태로 둔다.

## 8. 구현 현황 (2026-11-12, 로컬 구현·테스트까지. 운영 DB·함수 배포·푸시·플래그는 하지 않음. 브랜치 feat/behavior-events)

설계 대비 달라진 점(구현하며 확정):
- 마이그레이션 번호는 **013_events.sql**(012 는 주간 보상이 사용). 객체: `ev_raw` `ev_session` `ev_daily` `ev_rollup_log`, 함수 `ev_ingest` `ev_rollup(day)` `ev_prune(raw_days=14, session_days=90)` `ev_maintain()`(어제까지 미집계 날 집계 + 정리) `ev_merge_counts`. 전부 RLS 켬·정책 없음·함수는 service_role 전용. 롤백은 파일 머리 주석.
- `hd` 는 `ev_raw` 에 `s=last 화면`, `n={vis,play,act,rec}` 로 저장. 세션 `vis_s/play_s/act_s` 는 같은 sid 의 최댓값. 강제 종료 복구 `rec=1` 은 옛 sid 로 별도 배치로 간다(`ended_clean` 은 0 유지).
- 서버: `submit-score/events.ts`(`ev` 분기는 `index.ts` 에서 ps/fr/점수 경로·rate_limit 앞). 본문 4KB·이벤트 30개·**이벤트당 200바이트**(설계 120 은 `re` 가 넘어 조정). `re.n` 키는 축약(`dr mg sl up rg tk lk au sp` = draw merge sell up rng ticket lock auto spd). 영웅 id 는 `^[a-z0-9_]{1,16}$`(서버가 영웅 목록을 갖고 있지 않아 형식만 검사).
- 기기 해시 = `sha256(EV_SALT + device_id)` 앞 16자. **시크릿 `EV_SALT` 가 없으면 기록을 건너뛰고(로그 1줄) `keep:0` 으로 응답**한다. 속도 제한은 함수 메모리(기기 해시당 분당 12회, 초과 429, 인스턴스 재시작 시 초기화).
- 샘플링: 환경변수 `EV_SAMPLE_PCT`(0~100, 기본 100). 기기 해시 앞 2자리로 결정(기기 단위). 응답 `{ok, keep:0|1, sample}`; 클라는 `keep:0`(제외·솔트 없음)을 받으면 하루(`malang-ev-skip`) 쉬고, 429 를 받으면 그 세션은 중단.
- 클라: `track.js`(window.Track 하나), 플래그 `CONFIG.ANALYTICS`(기본 false: 리스너·타이머·네트워크·저장 전혀 없음), 옵트아웃 `malang-ev-off`, 메뉴 `#evOpt` 한 줄(플래그 off 면 숨김). 전송은 text/plain·응답 무시, 숨김 때만 sendBeacon. `S.round`/`S.score()` 는 홈 이탈 판의 요약에만 쓴다. 판 중 30분 넘게 숨은 뒤 새 세션이 되면 이전 판을 `re ex=bg` 로 보낸다.
- 훅(ui.js): `scr` — showNick/Rename/Import/Profile/Prob/SeasonClosed/Ranks(`ranks_{season|points|mine}`, lg)/uiGameOver(over)/goHome(home)/최초 home. `rs` — startRun(`rand|mine|ps`)·restartGame. `re` — uiGameOver(end)·goHome(home, `Track.home()`)·세션 롤오버(bg). `tap` — document click 위임(`TAPMAP`, track.js)과 `#evOpt`. seasons.js: `ps_gate/list/detail/invite/join/wizard`. myhero.js: `market`(open), `hero_pick`, `hero_sheet`, `hero_new`. 마켓 구매 `tap buy` 는 구매 성공 지점이 불명확해 넣지 않았다(M6 미구현).
- 시작 시 첫 세션의 `env.new=1` 은 이미 쓰던 기기도 포함한다(기존 사용자는 처음 켜는 시점에 한 번 `new` 로 보임).
- sw.js: `CACHE_VERSION` v45-ev-track, SHELL 에 `track.js` 추가.

### 8.2 대시보드용 집계 SQL·JSON 스키마 (실행 검증 안 함)

- `ev_actions.json` `{lg, runs, dr, mg, sl, up, rg, tk, lk, au, sp}`(판당 평균): `select lg, count(*) runs, round(avg((n->>'dr')::int),1) dr, round(avg((n->>'mg')::int),1) mg, round(avg((n->>'sl')::int),1) sl, round(avg((n->>'up')::int),1) up, round(avg((n->>'rg')::int),1) rg, round(avg((n->>'tk')::int),1) tk, round(avg((n->>'lk')::int),1) lk, round(avg((n->>'au')::int),1) au, round(avg((n->>'sp')::int),1) sp from ev_raw where e='re' and day>=current_date-14 group by lg`
- `ev_sessions_daily.json` `{day, sessions, devs, new_devs, avg_vis, avg_runs, clean_pct}`: `select day, count(*) sessions, count(distinct dev) devs, count(distinct dev) filter (where is_new=1) new_devs, round(avg(vis_s)) avg_vis, round(avg(runs),2) avg_runs, round(100.0*avg(ended_clean)) clean_pct from ev_session where day>=current_date-90 group by day order by day`
- `ev_daily_top.json` `{day, e, key, cnt, devs}`(원본 14일 이후에도 남는 건수): `select day, e, key, sum(cnt) cnt, sum(devs) devs from ev_daily where day>=current_date-90 group by 1,2,3 order by 1,4 desc` (`devs` 는 버전별 합이라 근사)
- 나머지(`ev_funnel` `ev_dwell` `ev_screens` `ev_taps` `ev_hours` `ev_cohort` `ev_exit`)는 §5.1 표 그대로. 표본이 샘플링(`EV_SAMPLE_PCT`<100)이면 응답 `sample` 로 배율 보정.
- 모든 JSON 은 행 배열(`[{...}]`), 데이터가 없으면 `[]`(대시보드는 '수집 전' 표시).
