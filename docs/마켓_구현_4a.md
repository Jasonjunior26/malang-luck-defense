# 마켓 구현 4a (규칙·데이터·저장, UI 화면은 4b) — design/v1, 미커밋·미배포

**변경 규칙(GAME_VER 8 -> 9, 서버·클라 모두 ui.js 한 곳에서 읽음, engine ENGINE_VER "9")**
- 능력(수치 24종, 영웅 근력·지휘 포함)은 영웅당 2종만(`MY_ABILITY_MAX`). 같은 능력 레벨업은 허용, 교체·환불 없음. validateMine 이 3종 이상을 `mine 능력 수 초과`로 거부(서버 강제).
- 스킬은 칸별 소유·장착: 기본공격 8종(id `sk_*`, 1·2단계, 100/200), 필살 7종(id `ul_*`, 2·3단계, 250/400; 2단계 4종은 양쪽에 따로). 선행: 기본공격 2단계=기본공격 1단계, 필살 3단계=필살 2단계(필살 2단계는 조건 없음).
- 장착 칸 = 기본 1 + 필살 1(`MY_EQUIP_MAX=2`는 칸 수). 빈 칸이면 그 공격은 일반 공격(game.js defOf: 기본공격 스킬이 필살을 대신하지 않음 — 게임 동작 변경).
- 옛 배열 equip 은 서버가 받지 않음(400 bad_mine). GAME_VER 8 클라는 ver 검사에서 먼저 409 라 별도 호환 코드 없음.

**데이터 구조**: `mine={design, items:{능력≤2 + 스킬 id:1}, equip:{basic:"sk_*"|null, ult:"ul_*"|null}}`. 클라 저장 `malang-myhero2` = `{v:2, mig:2, rs:1, coins, note, mnote:{refund,n}|null, heroes:[{design,name,own,equip:{basic,ult}}]}`. 항목 필드: `cat`(ability/basic/ultimate), 능력은 `grp`(atk/hero/reward/eco/guard/special), 스킬은 `slot`(basic/ult)·`tier`.

**마이그레이션(mig 1->2, load 1회, 키 유지)**: 능력 3종 이상 영웅은 능력 own 전부를 GAME_VER 8 가격(`MY_OLD_COST`)으로 환불해 코인에 합산하고 능력 초기화, `mnote`(환불액·영웅 수)로 모달 1회 안내. 2종 이하는 그대로. 스킬 유지: 옛 1·2단계 -> 기본공격 소유, 옛 3단계 -> 필살 소유(`ul_`). 필살 3단계가 있는데 필살 2단계가 없으면 보유 2단계 스킬 하나를 필살 칸 소유로 무상 부여, 옛 필살 칸 장착 2단계도 필살 소유 무상 부여. 장착 [a,b] -> a 가 1·2단계면 basic, b(또는 a 가 3단계)가 2·3단계면 ult. 환불 대상 없으면 안내 없이 mig 만 올림.

**가격(5 단위 반올림 50×V×g^(L-1), 효과 수치는 그대로)**: 능력 총액 17,985 -> 15,960(-11%), 스킬 3,480 -> 3,400, 전 품목 19,360(검토서 합계 18,210 은 표 소계와 안 맞아 코드 합산 기준). 예: 공격 훈련 1590->1360, 영웅 근력 1090->2450, 보스 현상금 395->720, 코인 행운 950->365, 보스 약화 655->300, 행운 뽑기 1650->1000(200/320/480). 나머지는 검토서 A-3 표와 총액 일치(테스트).

**테스트**: build_engine 후 test_myhero 290/0(새: 3번째 능력 거부, 레벨업 허용, 칸별 구매·장착, 마이그레이션 함수·load 통합, 서버 거부 케이스, 가격 총액), test_function 61/0, test_replay 15/0, test_rules 110/0, test_build 81/0, test_friends·private·queue·seasons_ui·home_flow·check_globals 통과, test_season_rank 64/0(ENGINE_VER 기대값 9로 수정). test_board 1건 실패는 변경 전에도 동일(p_is_mine 정규식, 이번 범위 밖).

**4b UI 훅(data.js / window.MyHero)**: `canBuy(own, item|id, coins?) -> {ok, code:""|none|max|req|slots|coin, reason(해요체), cost}`, `MyHero.buyCheck(designId, itemId)` 같은 반환, `MyHero.buy(designId,itemId)->bool`(스킬은 해당 칸이 비면 자동 장착), `MyHero.equipSlot(designId,"basic"|"ult",skillId|null)->{ok,reason}`, `myAbilities(own)->id[]`, `myReqTxt(item)`, `MY_CATS`·`MY_GRPS`·`MY_ABILITY_MAX`·`MY_SLOTS`. 현재 UI 는 마크업·CSS 변경 없이 새 구조로 동작(탭 3개, 능력 탭에 효과 종류별 h3, 내 능력 N/2 한 줄, 능력 가득이면 카드에 잠금 사유).

**남은 위험**: ① 능력 2종 제한으로 최대 전력 급감(검토서 위험 ①), 수치 상향은 별도 결정 — tools/sim_bot.mjs 의 풀빌드·EQ 기본값은 옛 구조라 갱신 필요. ② 단일 단계 능력(공명·훈장·뽑기 할인)이 한 칸 독식. ③ 오래된 탭이 mig 1 값을 덮어쓰면 환불이 한 번 더 계산될 수 있음(코인은 그 탭 값 기준이라 영향 작음). ④ 마이그레이션의 무상 필살 소유 부여는 설계 판단(보유 스킬 유지 목적). ⑤ 배포 순서: 함수(engine 9)와 클라를 같은 시점에, 구 클라는 409.
