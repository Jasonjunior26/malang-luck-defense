- ui.js 연결점: api() 가 `ps*` 액션에 JWT 부착 / startRun(mode, seed, rules) (rules 없으면 SEASONS.clear) / restartGame 맨 위 SEASONS.run() 분기 / uiGameOver 의 `priv` 분기(최고점 키 malang-best-ps, #rk 는 SEASONS.finish 가 채움) / bindUi 끝 `$("seasons").onclick`, `initPlayer` 뒤 SEASONS.boot().
- 시즌 판의 S.mode 는 game.js 가 "daily" 로 만들므로(GAME.start 는 practice 외엔 daily) 구분은 SEASONS.run()!=null 로 한다. 일반 submitScore 는 시즌 판에서 호출되지 않는다.
- index.html: 타이틀 `.trow`(랭킹/시즌 한 줄), CSS `.ps*` 블록(.rows 규칙 아래). sw.js CACHE_VERSION v8-private-seasons.
- 테스트: tools/test_seasons_ui.mjs (vm 으로 data.js+seasons.js 로드, 가짜 api).

## [HUD/하단바/홈 정리, v9-hud-home-rank]
- index.html: HUD 는 `#hud` grid 4칸(wave/score/min/mob), 칩 높이 44px 고정, 진행바는 칩 바닥 3px 띠 (CSS 블록 "HUD 통일", 구 칩 규칙 뒤에 덮어씀). `#bar2` 는 6칸 grid: 강화·판매·배속·랭킹(#rank)·소리·홈(#home). 확률표 버튼은 강화 시트 안(#probHelp)으로 이동. 자동 버튼은 의도적으로 없음.
- ui.js: `goHome()`(startRun 앞) = 홈 확인 후 SEASONS.clear + 타이틀 복귀. 타이틀 시작 계열 버튼은 `guard()`(bindUi)가 모달 열림/직후 600ms(`_modalAt`) 클릭을 무시. 랭킹 버튼은 showRanks 가 modal() 로 S.paused 처리.
- 시뮬 타이밍(조사): startRound 는 newGame 안에서 호출(game.js 57), 1라운드 첫 몹은 첫 update 틱(0.017s)에 spawn(spawnT=0). CONST.ROUND_SEC·SPAWN_FRAC 는 시뮬에서 안 쓰임(ROUND_SEC 은 HUD 진행바만).

## 랭킹 빌드 요약 (build) - 006_score_build
- game.js: `S.topGrade`(newGame 초기 0, placeUnit 3개 성공 지점에서 max 갱신) / `calcBuild()`(gameOver 바로 위) -> result.build = `{clans:[{n,lv}]x4, top}`. n=종료 시 필드 무리별 유닛 수(히어로 제외), lv=종료 시 S.lv[c](구매+보너스+공명, 상한 35), top=판 중 최고 등급 id.
- replay.js: result.build 반환 + `cleanBuild()`(모양·범위 검증, 이상하면 null). index.ts/private.ts 가 p_build 로 RPC 전달.
- DB: supabase/migrations/006_score_build.sql (scores.build, 뷰 2개+season_best_internal, submit_score_season/private, private_season_leaderboard, player_profile). 구 기록은 build=null.
- 클라: ui.js `buildTag`(heroTag 위) - showRanks 줄/내 기록, seasons.js 프라이빗 순위표. CSS `.rows small.bd`(index.html).
- 테스트: tools/test_build.mjs. GAME_VER 는 그대로(점수 불변).
