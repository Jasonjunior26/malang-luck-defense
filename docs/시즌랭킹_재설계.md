## 1. 현행 구조 (변경 전)
- 시즌: `data.js` `SEASONS` 배열(수동 추가, 시즌 1 = 10/27~11/15). 클라 `phaseNow()`, 서버 `seasonPhase(kstDate(now))`(engine.js 에 복사). 시즌 밖이면 서버가 `season_closed/not_started` 거부, 시즌 사이는 공백.
- 저장: `scores`(device_id, mode='daily', seed 별 한 줄, season, is_mine). 순위: 뷰 `season_best_board`(009: 시즌·리그별 이름당 최고 1건, 점수↓ 달성시각↑ device_id) -> 공개 뷰 `leaderboard_season`.
- 랭킹 모달: 탭 시즌/오늘/내 기록 + 리그 토글. 시즌 탭은 `leaderboard_season` limit **1000**, 오늘 탭은 `leaderboard_daily` limit **300**(판마다 시드가 달라 한 사람이 여러 줄) 후 클라에서 이름 중복 제거, 매 탭·리그 전환마다 재조회 + `api("profile")`(Edge Function) 동시 호출. 컬럼 폴백은 후보 3개를 연속 시도(장애 시에도 3회).
- 홈 시즌 박스(`refreshTitle`): 1위 REST 1회 + `api("profile")` 1회를 **홈 진입·판 종료·이름 변경·이전 등 refreshTitle 이 불릴 때마다**(앱 시작은 중복으로 2회).
- 제출: 판이 끝날 때마다 무조건 `submit`(서버가 입력 로그를 재생하는 CPU 비용이 큰 호출).

### 동점 규칙
- **시즌 순위**(같은 점수): 먼저 달성한 기록 우선(`played_at` 오름차순), 그래도 같으면 `device_id`. 순위는 항상 1,2,3... 로 확정(공동 순위 없음) -> 승점 대상 3명이 항상 유일하게 정해짐. 같은 사람이 같은 점수를 다시 내도 기록은 갱신되지 않으므로(`score < excluded.score`일 때만 갱신) 달성 시각이 늦춰지지 않음.
- **누적 승점**: 위 표대로. 승점·금·은·동이 모두 같으면 공동 순위.

### 시각·경계 규칙
- **기준 시계는 서버**(Edge Function `nowMs()`, KST). 저장되는 시즌 = **제출이 서버에 도착한 시각의 시즌**. 클라이언트는 표시·캐시 키에만 자기 시계로 시즌을 계산하고, 저장 시즌은 서버 응답(`season.id`)을 따른다.
- **진행 중 판**: 토요일 23:55 에 시작해 일요일 00:03 에 끝난 판은 **새 시즌(일요일)** 에 올라간다(도착 시각 기준). 반대로 토요일 23:59:59 에 도착한 제출은 이전 시즌, 00:00:00 은 새 시즌(테스트 `경계`).
- **오프라인 큐**: 큐 항목에 시즌 id 를 적어 두고, 시즌이 바뀐 뒤 flush 할 때는 **버린다**(서버는 도착 시각 시즌에 저장하므로 지난주 기록이 새 시즌을 오염시키지 않도록). 구 클라이언트(시즌 필드 없음)는 도착 시각 시즌에 저장됨.
- **기기 시계 오차**: 기기 시계가 틀리면 홈/랭킹 모달의 시즌 표시와 캐시 키가 어긋날 수 있다. 저장은 항상 서버 기준. 끝난 시즌을 영구 캐시하는 조건은 '종료 후 10분 경과'(시차 보호, `isFinal`)이며, 누적 승점 캐시는 시즌 시작 후 10분 안에 받은 값은 짧게만 신뢰.
- **승점 확정 시점**: 일요일 00:00 KST 이후(`season < season_current()`) 첫 조회부터 지난 시즌 TOP3 가 승점에 반영. 크론 불필요(§4).

## 3. 서버 구조 (마이그레이션 010, 크론 없음)
- `season_current()` : SQL 로 같은 식 구현(앵커/7일/KST). 테스트가 정적 점검.
- `season_final_points`(내부) : `season_best_board` 에서 `rank<=3 and season < season_current()` -> 승점 3/2/1.
- `leaderboard_points`(공개) : 리그(`is_mine`)별로 승점 합·금은동·마지막 시즌, `rank()` 로 순위.
- **크론이 필요 없는 근거**: 끝난 시즌의 `season_best_board` 는 새 쓰기가 없어(서버가 도착 시각 시즌에만 저장) 항상 같은 값 -> 뷰가 곧 불변 집계. 지연 비용은 조회 시 계산뿐이며 TOP3×시즌 수(주 1회 증가)라 작고, 클라가 시즌 id 키로 영구 캐시하므로 시즌당 사용자별 1회만 계산된다. (사용자 수천 명 이상에서 느려지면 `season_points_snapshot` 테이블 + 시즌 전환 후 첫 조회 때 채우는 rpc 로 전환 가능 — 그때까지 보류.)
- 한계: 플레이어가 닉네임을 바꾸면 승점 표의 이름도 바뀜(device_id 기준 집계). 운영자가 점수를 삭제하면 지난 시즌 순위·승점이 바뀔 수 있음(의도된 수동 개입).
- `submit-score`: **코드 변경 없음**. `engine.js` 만 재생성(새 시즌 규칙, GAME_VER 4 유지). 서버는 시즌을 날짜에서 직접 계산하므로 '설정 행' 의존이 없다.

## 4. 클라이언트 구조
- `data.js`(SEASONS-BEGIN~END, 서버 공유): `SEASONS`(옛 시즌), `WEEK_ANCHOR`, `seasonById`, `seasonIdOf`, `seasonPhase`(live/before/none, `after` 폐지), `addDays`.
- `ui.js` 랭킹 구간(`// ---- 랭킹 캐시`): `rcGet/rcSet/rcDrop`(localStorage `malang-rc:*`, LRU 16), `fetchRanks`·`fetchMyRank`·`fetchPoints`·`fetchProfile`, `tryVariants`(서버 능력 30분 기억), `tallyPoints/localPoints`(서버 미설정 폴백, 뷰와 같은 규칙), `sbestGet/Set`(개인 시즌 최고), `showRanks(tab, again, board, sid, force)`.
- 랭킹 모달: 탭 `🏆 시즌 랭킹 | 🏅 누적 승점 | 🙋 내 기록`, 리그 토글, 시즌 `◀ 이전 / 다음 ▶`(지난 시즌 = 종료·최종 순위·승점 표시), 제목에 리그명, `🔄 새로고침 · HH:MM 기준`(30초 간격 제한). 상위 100명 + 내 순위 고정줄.
- 오늘 탭 **제거**(§6-c).

## 6. 이전 점검 건
- (a) 나만의 영웅 판 종료 화면: 소제목 `🦸 나만의 영웅 리그 · 시즌 N`, 버튼 `🏆 나만의 영웅 리그 랭킹 보기`(운빨 판은 `🎲 운빨 리그`). 랭킹 모달 제목에도 리그명을 크게 표시.
- (b) '준비 중' 보장: 재검토 결과 `rankUrls` 폴백 코드 자체는 맞았다(`is_mine` 400 -> 무필터 후보 `bd=false` -> 내 영웅은 `null`). 다만 ① `MYHERO_RANKED:false` 이면 서버에 내 영웅 기록이 있을 수 없으므로 **호출 없이 즉시 '준비 중'**, ② 폴백 결과를 능력으로 기억·캐시해도 내 영웅 보드는 `unsup` 으로만 캐시, ③ 새 캐시 키가 리그·시즌별이라 섞이지 않음. 점검 중 11명이 보인 건 이전 번들(서비스워커가 구 `ui.js` 를 제공 - stale-while-revalidate)이었을 가능성이 크다. 테스트 `test_season_rank.mjs`에 가짜 서버(is_mine 400/일반 200, MYHERO_RANKED true/false)로 재현·고정.
- (c) '오늘' 탭: 판마다 시드가 달라 한 사람의 기록이 여러 줄이고 limit 300 + 클라 중복 제거라 낭비가 가장 큼, 주간 시즌에서는 시즌 순위와 정보가 겹침 -> **삭제**하고 자리를 누적 승점 탭으로 사용.

## 7. 마이그레이션·배포 순서
1. (서버 승인 후) SQL Editor: `007_hero_name.sql` -> `009_board_split.sql` -> `010_season_points.sql`(각각 재실행 안전).
2. `node tools/build_engine.js` (이미 실행해 `engine.js` 포함) -> `supabase functions deploy submit-score --no-verify-jwt`. **이 순간부터 서버가 주간 시즌**(010 이 아직 없어도 승점 뷰만 없을 뿐이며 클라는 '준비 중'으로 폴백).
3. 페이지 배포(`sw.js` v25). 구 클라이언트는 옛 규칙(시즌 1 만, 11/15 까지)으로 시즌 id 1 보드를 조회하므로 서버가 주간 시즌 2 로 저장하는 동안 표시만 어긋난다(저장은 서버 기준이라 데이터는 정상). 서비스워커가 새 번들을 받으면 해소되므로 함수와 페이지는 **같은 시각에** 배포.
4. 내 영웅 리그를 열 때: `config.js MYHERO_RANKED:true` 클라이언트 배포(009 + 함수 선행 필수).
- 순서를 바꿔도 안전한 점: 010 이 없으면 승점 탭은 '준비 중'. 009 가 없으면 010 적용 불가(뷰 의존) — 이때는 1번 순서를 지킬 것.
