# 주간 랭킹 보상 + 마이히어로 능력 조정 (GAME_VER 9 -> 10) 스펙

작성 2026-11-10, 마스터 확정본. 구현 에이전트 3명(A 밸런스·B 서버·C 클라)이 이 계약만 지키면 서로 충돌하지 않는다. 브랜치 `feat/weekly-rewards`(워크트리 `C:\Users\USER\orca\projects\Quick-game-wr`). **모든 작업은 이 워크트리 안에서만.** 원 저장소 폴더(`Quick-game`)는 건드리지 않는다.

## 사용자 요구 원문 요약
1. 마이히어로 능력은 **같은 효과의 일반 히어로 값의 120%** 로. 대응 능력이 없으면 그대로.
2. 마이히어로 능력 구매 코인비용 **현재의 1.5배**. **이미 산(보유) 능력은 건드리지 않는다**(보상 개념, 환불·재결제 없음).
3. 주간 랭킹(운빨 / 마이히어로 리그 각각) 보상.
4. 보상은 시즌 종료 후 합산해 일괄 지급, 내용은 **전체 팝업으로 고지**(경쟁 유도).
5. 각 리그 1위는 보상금 +100.

## 보상 공식 (확정, 서버가 계산)
- 리그 = 운빨(`is_mine=false`) / 마이히어로(`is_mine=true`). 리그마다 따로 계산.
- N = 그 시즌·리그 보드의 순위권 인원 수(`season_best_board` 행 수, 한 사람 1행).
- **K = max(10, ceil(0.3 x N))** (정수 연산으로. 부동소수 금지). 보상은 1..K위.
- 기본 보상 base(r, K): 선형 200(1위) -> 10(K위)를 **일의 자리 올림(10 단위)**.
  - 정수식(검산 완료): `num = 200*(K-1) - 190*(r-1)`, `base = ceil( num / (10*(K-1)) ) * 10` (정수 올림 나눗셈: `(num + 10*(K-1) - 1) / (10*(K-1))`). K=10: r1..r10 = 200,180,160,140,120,100,80,60,40,10. 마지막(K위)은 항상 10, 1위는 항상 200. K>=10 이라 0 나누기 없음. **K=10, 11, 15, 34, 100, 1000 기대표를 단위 테스트로 못 박는다**(SQL 과 JS 참조 구현이 같은 정수식을 쓰고, 표는 손으로 계산).
  - 단조 비증가여야 하고 모든 r 에 대해 10 <= base <= 200 이고 10의 배수.
- 1·2·3위 별도 보상금: +100 / +70 / +50.
- 각 리그 1위는 추가 +100(운빨 1위, 마이히어로 1위 각각). 해석: "그 리그의 1위가 보너스 100을 더 받는다". 한 사람이 두 리그 1위면 각 리그 보상을 따로 합산해 받는다. (해석을 바꾸려면 서버 상수 한 줄 `TOP1_EXTRA`.)
- 1위 총액 = 200 + 100 + 100 = **400**, 2위 = 180+70 = 250, 3위 = 160+50 = 210, 10위(K=10) = 10.
- 한 사람이 같은 시즌에 두 리그 모두 순위권이면 두 줄(리그별) 보상을 모두 받는다(합산해 한 번에 지급되지만 팝업에는 리그별로 보인다).
- 지급 시점: 시즌 종료(일요일 00:00 KST) 이후 **첫 조회 때** 정산(크론 없음, 지연 정산). 지난 시즌 중 아직 정산 안 된 가장 이른 시즌부터 `FIRST_REWARD_SEASON`(= 2) 이상만.
- 이미 끝난 시즌 1 은 보상 없음. 시즌 2(11/08~11/14)부터 대상.
- 악용 방지(이번엔 최소한): 보드에 오른 행(서버가 검증한 제출)만 대상. 최소 인원·계정 연결 요구는 두지 않는다 -> 알려진 위험으로 문서에만 기록(다계정 인원 채우기).

## 서버 API 계약 (submit-score 함수, device_id 기반, JWT 불필요)
둘 다 `POST` 본문에 `device_id`(UUID) 필수. 기존 `action` 분기 구조를 따른다. `profile` 과 같은 읽기 한도(rate limit kind `read`) 사용.

`action:"rewards"` -> 
```
{ ok:true,
  cur: <현재 시즌 id>,
  last: { season: <직전 끝난 시즌 id>,            // FIRST_REWARD_SEASON 미만이면 last:null
          leagues: {
            luck: { n:<순위권 인원>, k:<보상 범위>, top:[{rank,name,hero?,total}] /*1~3위*/ },
            mine: { n, k, top:[...] } } },
  pending: [ { season, league:"luck"|"mine", rank, base, bonus, total } ... ],   // 이 기기의 미수령 보상(모든 지난 시즌), 없으면 []
  tbl: { top:200, last:10, b1:100, b2:70, b3:50, extra1:100, ratio:30 }          // 팝업의 안내문용 상수
}
```
- 호출 시 서버가 미정산 지난 시즌을 정산(멱등, 동시 호출 안전: advisory lock 또는 `insert ... on conflict do nothing`).
- `name` 은 닉네임(공개 정보). hero 는 마이히어로 리그일 때 영웅 이름(있으면).

`action:"rewardAck"` + `seasons:[id,...]` -> `{ok:true, acked:<건수>}` : 이 기기의 해당 시즌들 보상을 수령 완료(`claimed_at`) 표시. 멱등. 본인 보상만.

## DB (마이그레이션 `supabase/migrations/012_season_rewards.sql`)
- 테이블 `season_rewards(season int, is_mine bool, device_id uuid, rank int, base int, bonus int, total int generated/계산 저장, settled_at timestamptz default now(), claimed_at timestamptz null, primary key(season,is_mine,device_id))`. RLS 켜고 정책 없음(함수가 service role 로만 접근). 익명 키로 읽기 불가여야 한다.
- 정산 메타 테이블 또는 `season_reward_runs(season, is_mine, n, k, settled_at)` 로 "이 시즌·리그 정산 완료"를 한 번만 기록(0명 보드도 완료 처리, 재정산 금지).
- 순수 함수 `reward_base(r int, k int) returns int` (immutable) — **데이터 없이 호출해 검증 가능**하게 분리. 배포 직후 `select r, reward_base(r,10) ...` 로 확인한다.
- 정산 함수 `season_rewards_settle(p_season int)` (security definer, 멱등). 기존 `season_best_board` 의 rank 컬럼·`season_current()` 를 재사용한다(009·010 참조).
- 롤백: 새 객체뿐이라 `drop` 으로 되돌릴 수 있음. 기존 객체 변경 금지.

## 클라이언트 (C)
- 보상 수령은 **로컬 코인 지급**(코인은 `malang-myhero2` localStorage). 이중 지급 방지: 저장 객체에 `rw:[시즌id...]`(이미 지급한 시즌) 추가, 지급 전 확인·지급과 기록을 한 번의 save 로. 그 다음 `rewardAck`. ack 실패해도 로컬 `rw` 때문에 다음에 재지급되지 않고 ack 만 재시도.
- 앱을 열고 홈에 들어간 뒤(닉네임 등록된 기기, 온라인) 시즌별 1회 `rewards` 호출. 직전 끝난 시즌 팝업을 이미 본 적 있으면(로컬 `rwSeen:시즌id`) 띄우지 않되, `pending` 이 있으면 항상 띄운다.
- **전체 팝업**(전체 화면 모달, 닫기 전 다른 조작 불가): 제목 "지난 주 랭킹 보상" + 시즌 표기. 구성: (1) 내 결과 블록(수령액 큼직하게, 리그별 순위·내역, `받기` 주 버튼 1개 -> 지급+ack) 또는 보상이 없으면 응원 문구와 "상위 30%(n명)까지 보상" 안내 + `확인` (2) 두 리그의 1~3위 닉네임·총액 (3) 보상표 요약(1위 400 · 2위 250 · 3위 210 · … · 상위 30%까지 최소 10) (4) 이번 주 도전 문구. 경쟁심을 자극하는 톤이되 과하지 않게.
- 랭킹 모달에 한 줄 안내 칩: "주간 보상 · 1위 400🪙 · 상위 30%까지".
- 개발·검증용 `?rwdemo=1` : 가짜 데이터로 팝업만 띄움(코인 지급·서버 호출 없음). 운영 배포본에서 눈으로 확인하는 용도.
