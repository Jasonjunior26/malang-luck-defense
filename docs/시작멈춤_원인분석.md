# 게임 시작 후 몬스터 안 나옴 (랭킹 열었다 닫아야 진행) 원인 분석

## 요약
1. 원인: data.js 의 전역 `const SEASONS`(배열, 10-27 c4d84f7)가 seasons.js 의 `window.SEASONS`(객체, 10-30 34ac619)를 가려, ui.js 의 `SEASONS.clear()` 가 TypeError. startRun 이 `TITLE_ON=false` 까지만 실행하고 중단되어 GAME.start 의 `S.paused=false` 가 안 돌았다.
2. 충돌은 34ac619(14:32)에서 처음 생겼고, 그 전엔 seasons.js 자체가 없어 문제가 없었다. 테스트는 vm 에서 바깥 `ctx.SEASONS` 로만 접근해 가림 현상을 못 봤다.
3. 첫 수정(38ba24f)은 증상(클릭 관통)만 막았다. 수정은 `window.SeasonMod` 로 이름 변경(미커밋), 재발 검사는 `tools/check_globals.mjs` 신규.

## 타임라인 (git log -S 근거)
- 10-27 14:58 c4d84f7: data.js 에 `const SEASONS = [...]` (시즌 기간표) 도입.
- 10-30 14:32 34ac619: seasons.js 신규(`root.SEASONS = {open, clear, run...}`), index.html 에 로드, ui.js 에 `window.SEASONS && SEASONS.clear()`, `SEASONS.open()` 등 호출 도입. 같은 커밋에서 충돌 성립.
- 10-30 14:49 38ba24f: [랭킹] 버튼/유령 클릭 가드 추가. 이때 `$("seasons").onclick = ... SEASONS.open()` 도 추가(같은 TypeError 대상).
- 오늘 이전에 괜찮았던 이유: ui.js 에 SEASONS 참조가 없었고 seasons.js 도 없었다. 오늘 3시간 안에 두 이름이 처음 같은 페이지에 공존했다.
- 메커니즘: 클래식 스크립트의 최상위 const 는 전역 렉시컬 환경에 들어가고 `window.X` 프로퍼티보다 우선한다. 그래서 `window.SEASONS`(객체, 참)는 가드를 통과하고, 뒤의 bare `SEASONS`(배열)에는 `.clear` 가 없다.
- 증상 연결: startRun 에서 `TITLE_ON=false`(타이틀 숨김) 후 예외 발생 → S.paused 가 true 로 남아 몬스터 정지. [랭킹] 모달을 닫으면 ui.js 의 모달 닫기 코드(`!TITLE_ON && !S.over` 이면 `S.paused=false`, 366행)가 우연히 정지를 풀어 진행된다. 이것이 "열었다 닫으면 진행" 의 정체다. goHome/restartGame/uiGameOver 도 같은 위치에서 중단된다.
- 부수 피해: [시즌] 버튼(`SEASONS.open()`)도 배열이라 TypeError. 프라이빗 시즌 UI 전체가 배포본에서 죽어 있었다.

## 왜 테스트가 못 잡았나
- tools/test_seasons_ui.mjs 는 `vm.createContext` 한 컨텍스트에 data.js, seasons.js 만 로드한다(ui.js, game.js 미로드). 즉 data.js 는 같은 스코프에 있었으나, 접근을 `ctx.SEASONS._t`(컨텍스트 밖에서 전역 객체 프로퍼티 조회)로 했다. 밖에서 읽으면 렉시컬 const 는 안 보이고 window 프로퍼티(객체)만 보여서 항상 통과한다.
- 실제 장애 지점인 "스크립트 안에서 bare `SEASONS` 를 평가" 하는 경로(ui.js 의 startRun 등)는 어떤 테스트도 실행하지 않았다. 순수 로직만 점검하는 설계라 UI 배선은 검증 범위 밖이었다.
- tools/test_home_flow.mjs(신규, 미커밋)는 이 배선을 보려는 시도이며, 충돌 수정 후 시작 흐름을 검증해야 한다.

## 왜 첫 수정이 실패했나
- 사용자 보고는 "[랭킹]이 게임 시작" 과 "시작 지연". 에이전트는 이를 타이틀 클릭이 관통(버튼 겹침)한 문제로 가정해 600ms 유령 클릭 가드 + stopPropagation 을 넣고 종결했다. 예외 로그/콘솔을 보지 않았고 배포본에서 시작 → 몬스터 확인 같은 end-to-end 재현을 하지 않았다.
- 관계(코드 추적): 예외 후 TITLE_ON=false 이므로 타이틀이 사라지고 화면은 게임판인데 정지 상태다. 이 상태에서 어떤 클릭이 모달을 열었다 닫으면 진행되므로 "[랭킹]을 누르면 시작되는 것처럼" 보인다. 클릭 가드는 이 경로와 무관하다.
- "게임 시작되고 몬스터가 나오는데 오래 걸린다" 가 같은 원인인지: 추측(확정 아님). 지연의 정체가 "정지 상태에서 사용자가 모달을 열고 닫기까지의 시간" 이라면 같은 원인이다. 다만 34ac619 이전(오전)에 보고된 지연이라면 시기상 다른 원인(오디오 초기화, 로그인 동기화 대기 등)일 수 있어 근거가 없다. 수정 후에도 지연이 남으면 별도로 측정할 것.

## 재발 방지
(a) 구조적 방어(제안)
- 시작 경로를 try/finally 로 감싼다: startRun/goHome/restartGame 에서 부가 호출(SeasonMod.clear, refreshTitle, 랭킹 갱신)은 `try { } catch (e) { reportError(e) }` 로 격리하고, 핵심 상태 전이(`TITLE_ON`, `S.paused`)는 finally 또는 마지막 줄에서 보장한다. 부가 기능 실패가 게임 진행을 막지 않게 한다.
- 전역 소유권 규칙: 윈도우에 내보내는 객체는 `*Mod` 접미사로 이름을 짓고, data.js 의 데이터 상수는 `*_TABLE` 처럼 구분한다.
(b) 자동화
- `node tools/check_globals.mjs` 를 배포 전(또는 sw.js 버전 올릴 때, 테스트 묶음)에 실행한다. 충돌 시 종료코드 1.
- test_seasons_ui.mjs 에 "ui.js 포함 같은 컨텍스트에서 startRun 호출 후 S.paused===false" 스모크를 추가하고, 접근은 컨텍스트 안 `vm.runInContext("SeasonMod")` 로 한다.
(c) 사용자에게 보이는 오류(제안만)
- `window.onerror`/`unhandledrejection` 에서 화면 하단 토스트("오류가 발생했습니다 [코드] 재시도") 표시, 시작 중(TITLE_ON 전환 직후)이면 자동으로 `S.paused=false` 복구 시도 후 타이틀 복귀 버튼 제공.
- 로그: 메시지, 스택 앞 3줄, 빌드 버전(sw.js 캐시 버전), 화면 상태(TITLE_ON, S.paused)를 localStorage 최근 20건 링으로 저장하고, 설정 화면에서 복사 버튼 제공. 서버 전송은 선택(Supabase 테이블 1개).
