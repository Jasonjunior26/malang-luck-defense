# 내 영웅 v2 스펙 (GAME_VER 7 배포 → 8 미배포: 전투력 상한 제거, 2026-11-08)

> **전투력 개념은 GAME_VER 8 에서 삭제됐다**(사용자 결정, 추후 라운드·난이도를 올릴 계획). 아래 본문의 '전투력·켜기/끄기·상한 40' 서술은 v7 기록이며, 현재 규칙은 마지막 절 '7. 전투력 제거(GAME_VER 8)' 가 우선한다.

## 1. 바뀐 점
- 나만의 영웅 리그 영웅 = **디자인 20종 중 하나**. 모든 디자인의 기본 능력은 같다(일반 공격만: 히어로 유닛 `shot`, 4번째마다 필살 x3). 운빨 리그 10영웅(HEROES)과 그 특수 능력은 이 리그에서 쓰지 않는다(HEROES 불변).
- 개성 = 코인 시장에서 산 능력 35종(수치 24 + 스킬 11, 카테고리 6). 산 수치 능력은 전부 항상 적용되고, 스킬은 장착 2칸(기본 공격·필살). (v7 의 전투력 상한 40·켜기/끄기는 v8 에서 삭제)
- 서버는 구매를 검증 못 하므로 `validateMine` 은 한도(품목 id·단계 범위·스킬 선행 조건·장착 ≤ 2)만 본다. 최악 = 영웅 1종 전 품목 보유 + 최강 스킬 조합(7절 봇 수치).

## 2. 데이터 계약 (data.js MYHERO-BEGIN~END, engine.js 가 export)
```
mine = { design: "<20 id>", items: { <품목id>: <켠 단계 1..max> }, equip: ["<스킬 품목id>", ...최대 2] }
```
- `items` 는 **이번 판에 켠 단계**(보유 단계 이하는 클라이언트 책임). 보유 단계(구매 기록)는 myhero.js 저장값에만 둔다(예: 영웅별 `own:{id:lv}` + `on:{id:lv}` + `equip`). 스킬은 pw 0 이므로 보유한 스킬은 전부 items 에 넣어 보낸다(선행 조건 검증용).
- `MY_DESIGNS` [{id,name}] 20개(순서 고정): bee goose weasel whale hedgehog chameleon frog penguin fennec owlsage fox cat bunny bear panda dragon unicorn octopus turtle raccoon.
- `MY_CATS` [{k,name,ico}]: atk 공격 / skill 영웅·스킬 / reward 보상 / eco 경제 / guard 방어·생존 / special 특수.
- `MY_ITEMS` [{id,name,ico,cat,max,pw,cost:[단계별 비용],txt:(l)=>문구, ap(fx,l) | 스킬: tier(1~3), sk:{fx,shot,aoe,st,pierce,k,cd}}]. `txt(l)` 은 l 단계 누적 효과.
- `MY_EQUIP_MAX`=2 (equip[0] 기본 공격 대체, equip[1] 필살 대체; 하나면 필살도 [0] 방식), `MY_FULL_COST`=영웅 1종 전 품목 비용(21465).
- `MY_REQ_TXT` {2:"1단계 스킬 하나 보유", 3:"2단계 스킬 하나 보유"}, `myReqOk(id, items)`, `myPower(items)`.
- `validateMine(m)` → `{ok:true, mine:{design,items(카탈로그 순, 0 제거),equip}}` | `{ok:false, err}`. 레거시 `{hero,up}` → `err:"mine_legacy"`.
- `applyMine(mine)` → 영웅 복사본 `{id:design, name:디자인 이름, rule:"일반 공격" | "기본: X · 필살: Y", fx, look:null}`. (옛 `applyMine(base, mine)` 2인자도 동작)
- `itemCost(id, lvNext)` (1부터, 범위 밖 -1), `mineTotalCost(mine)`, `mineCoinLv(mine)`(= items.coin), `coinsFor(R, kills, win, coinLv)` (식 불변, 4번째 인자가 코인 행운 단계). myhero.js settle 은 `coinsFor(..., mineCoinLv(s.mine))` 로 바꿔야 함.
- `migrateLegacyMine({hero|id, up})` → `{design, items:{}, equip:[], refund}`: 옛 강화 구매액 **전액 환불**(COST 60/100/160/240/340 누적), 디자인 = 옛 영웅 id. `MY_HERO`(MAX 3, COST, DIRS k/max)는 이 계산과 등록 수 MAX 용으로만 남김.
- game.js 새 fx 키: `heroAtk`(영웅 근력), `hsk`/`hsk2`(장착 스킬 정의). defOf(u, sup), launch 가 defOf(u, f.sup) 사용. 나머지 품목은 기존 fx 키(atkMul atkSpd rangeMul bossDmg roundDmg heroLvK killMul bossBonus startMin roundMin drawCost upCost sellMul bossTime mobSlow slowPlus bossHp resoEase mergeUp bossUp/bossUpEvery freeDraw burnDur).

## 3. 서버 / 버전
- **GAME_VER 6 → 7**(ui.js 한 줄). 이유: 같은 mine 이 v6 와 v7 에서 전혀 다른 게임이므로 옛 캐시 클라이언트(v6, {hero,up})는 409 `ver_mismatch` 로 새로고침 유도(정책 "옛 버전 점수 거부는 무방"). 운빨 리그 규칙은 불변이지만 ver 는 하나라 같이 올라간다.
- 레거시 {hero,up}: 정상 경로로는 ver 검사에서 먼저 걸린다. ver 를 7 로 맞춘 레거시 요청은 index.ts 가 409 `mine_legacy`. replay 도 거부. (한 버전 수용은 하지 않음: 옛 강화로 재생하면 v2 보드에 영웅 특수 능력 판이 섞이기 때문)
- 변경: data.js, game.js, ui.js(GAME_VER), supabase/functions/submit-score/{index.ts, engine.js(재생성)}, tools/build_engine.js(export 추가). replay.js·private.ts 무변경. DB 마이그레이션 불필요(p_hero 는 text, 디자인 id 그대로 저장).
- 배포 순서(사용자 승인 후, **단계 C myhero.js v2 와 같이**): 함수 재배포(engine.js v7·index.ts) → 클라이언트 push(sw CACHE_VERSION 올림). 함수만 먼저 나가면 v6 클라 전부 ver_mismatch 이므로 둘을 같은 시점에.

## 7. 전투력 제거(GAME_VER 8) · 스킬 분류 · 영웅 삭제 (2026-11-08, 미배포)
- **규칙**: data.js 에서 `MY_POWER_CAP`·`MY_POWER_ALL`·`myPower`·품목 `pw`·validateMine 의 '전투력 상한 초과' 삭제(`tools/build_engine.js` export 도). validateMine = 품목 id·단계 범위·선행 조건·장착 수만. GAME_VER 7→8, engine.js 재생성(ENGINE_VER "8"). 서버 재배포와 클라 푸시는 같은 시점(사용자 승인 후).
- **클라이언트(myhero.js)**: 보유한 수치 능력은 전부 항상 적용(켜기/끄기 ± 삭제). mineOf 는 own 단계를 그대로 items 로. 저장 `malang-myhero2` 는 호환(옛 `on` 필드는 읽어도 무시, 다음 저장 때 사라짐). 시장의 전투력 게이지·카드 '전투력 n' 태그, 장착 화면의 게이지·± 삭제(장착 화면 = 스킬 2칸 + 보유 능력 보기).
- **스킬 칸 분류 사실(game.js defOf/update, data.js applyMine)**: 스킬은 **칸 전용이 아니다.** 어느 스킬이든 equip[0](=기본 공격 칸, `fx.hsk`) 또는 equip[1](=필살 칸, `fx.hsk2`)에 들어간다. 필살 = 영웅 유닛 4번째 공격마다(피해 x3, 그 공격의 cd·모션은 hsk2). 스킬 1개만 장착하면 필살도 그 스킬. 그래서 '기본 공격 전용/필살 전용 스킬'은 없고, 같은 칸을 노린 스킬끼리만 서로 대체된다(칸이 하나씩이라). 마켓은 구역을 '수치 강화(영웅 근력·지휘, 능력 탭 전체)' / '스킬(칸 2개 안내)' 로 나누고, 스킬 카드에 장착 칸·들어갈 칸·두 칸 다 찼을 때 쓰는 스킬 이름을 구매 전에 보여 준다. 규칙 변경은 없다.
- **영웅 삭제**: 마켓 상단 🗑 / 영웅 선택(pickMine) 행의 🗑 → uiConfirm('이 영웅에 쓴 코인 🪙 N은 돌려받지 못하고, 산 능력과 장착도 모두 사라져요. 보유 코인은 그대로예요') → heroes 에서 제거(환불 없음, 코인은 영웅과 별개). 삭제 불가 사유 없음(진행 중인 판은 mine 사본으로 계속, again() 은 영웅이 없으면 운빨 리그). 삭제 뒤: 다른 영웅 시장 / 영웅이 없으면 20종 그리드(마지막 영웅도 삭제 가능). 같은 디자인 재등록 가능(능력은 처음부터). 영웅별 신기록(`malang-myhero-rec`)은 디자인 id 키라 재등록해도 남는다.
