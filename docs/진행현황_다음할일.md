## 0. 작업 규칙 (갈래 방지)
- **항상 `origin/main` 최신에서 시작한다.** 옛 브랜치·워크트리(예: `malrang-defense-social-evolution`)는 `main` 보다 뒤처져 있다. 그 위에서 이어 작업하지 말고 `git fetch && git merge origin/main`(또는 새 브랜치를 origin/main 에서 따기) 후 시작한다.
- 이 문서의 "배포 완료"로 표시된 항목은 **이미 운영에 올라간 것**이다. 다시 설계·구현하지 않는다. 아래 §6~§9 의 "(미커밋/미배포)" 표기는 옛 기록이며, 이 §0·§1 이 우선한다.
- 게임 규칙(data.js/game.js)이나 GAME_VER(ui.js)를 바꾸면 `node tools/build_engine.js` 로 engine.js 재생성 → 테스트 → **함수 재배포와 클라이언트 푸시를 같은 시점에**(안 맞으면 `ver_mismatch`).
- 히어로 id 는 10종뿐: bee goose weasel whale hedgehog chameleon frog penguin fennec owlsage. 옛 id(darami, hwarang, buung 등)는 없다.
- 운영 DB·함수 배포·푸시는 사용자 승인 후. 배포 순서: 마이그레이션 → 함수 → 클라이언트 → 플래그.
