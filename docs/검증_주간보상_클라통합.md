# 검증: 주간 보상 클라이언트·통합 (feat/weekly-rewards, 미커밋 작업본)

작성 2026-11-10, 독립 검증자. 읽기 전용 검토(이 파일만 작성). 보상표 마크업/CSS(D 재디자인 중)는 모양 검토에서 제외.

## 요약
- 차단: 없음.
- 중요 1건: 큐에 들어간 보상 팝업이 판 시작 직전에 열려 **판이 팝업 뒤에서 일시정지 없이 진행**될 수 있음(+ 그 상태에서 홈으로 가면 `showing` 이 영구히 true 로 남음).
- 그 외는 사소/의심. 통합(ui.js 양쪽 편집, 로드 순서, sw, config, engine 재생성)은 문제 없음. 테스트 전부 통과(test_board 1건은 원본에서도 동일 실패).

## 확정 결함

### [중요] 큐잉된 팝업이 판 시작과 겹침 — rewards.js:208-220, myhero.js:179, ui.js:384-391/1321
- `boot()` 은 fetch 직후 `TITLE_ON` 을 한 번만 확인하고 `queueModal(go)` 한다. fetch 가 끝날 때 다른 모달이 열려 있으면(가장 흔한 예: 홈에서 '내 영웅 리그' → `pickMine` 영웅 선택 창) `go` 가 MODAL_Q 에 들어간다.
- 사용자가 영웅 시트에서 시작을 누르면 myhero.js:179 `closeModal(); o.go(mineOf(x))` 순서다. `closeModal` 이 큐를 꺼내 보상 팝업을 연다(이때 TITLE_ON=true 라 `modal()` 은 S 를 멈추지 않음) → 곧바로 `startRun` 이 새 판을 시작한다. 결과: **랭킹 판이 보상 팝업 뒤에서 실시간 진행**(라운드 손해). `go` 안에서 TITLE_ON 을 다시 보지 않는다.
- 이어서 그 판에서 메뉴 → 홈(`goHome`)을 누르면 ui.js:1321 이 `MODAL_ON=false`·모달 숨김만 하고 Rewards 의 `close()` 를 거치지 않아 `showing=true`, keydown 리스너가 남는다. 이후 그 세션에서 `boot()` 은 항상 "busy"(보상 팝업 다시 안 뜸), ESC 를 누르면 남은 리스너가 `closeModal()` 을 불러 **다른 모달(랭킹 등)을 닫는다**.
- 앱 시작 경로도 같다: `syncAccount→initPlayer→SeasonMod.boot→Rewards.boot` 가 수 초 걸리는 동안 사용자가 영웅 선택 창을 열면 재현.
- 수정안: (1) `go = () => { if (g("TITLE_ON") === false) return; open(...) }` 처럼 큐에서 꺼낼 때 다시 확인(꺼낸 뒤 아무 것도 안 열면 closeModal 의 뒤처리가 생략되지만 startRun 직전이므로 무해. 필요하면 return 전에 남은 큐를 이어 실행). (2) `startRun` 첫 줄에서 `MODAL_Q = []` 또는 Rewards 대기분 제거. (3) Rewards 에 `reset()`(showing=false, 리스너 제거)을 두고 `goHome` 의 강제 정리에서 호출하거나, `open()` 의 `showing` 판정을 `showing && MODAL_ON && $("rwOk")` 처럼 실제 DOM 상태로 확인.

## 사소

1. **지급 저장 실패해도 ack** — rewards.js:213-216, ui.js:7. `lsSet` 은 예외를 삼킨다. 저장(코인+rw)이 실패해도 `ack` 가 나가 서버 `claimed_at` 이 찍히고 보상은 영구 소실, 화면은 "받았어요!". 수정: `grantReward` 뒤 `MH.rewarded()` 에 해당 시즌이 있는지 확인한 뒤에만 ack.
2. **완료 화면 금액이 실제 지급액이 아님** — rewards.js:92-94. `sum` = claim 합계. 다른 탭에서 먼저 받은 경우(grantReward granted 0) 또는 COIN_CAP 잘림 때도 "받았어요! 400" 표시. `granted` 를 이미 들고 있으니(138행) done 상태에서는 그 값을 보여 주거나 0 이면 "이미 받았어요".
3. **SEEN 기록 시점** — rewards.js:218. 받기 후 [확인] 전에 앱을 닫고 ack 도 실패했으면, 다음 진입 때 claim 은 stale 로 빠지고 `last.season !== seen` 이라 "이번엔 보상이 없어요" 팝업이 뜬다(방금 받은 사람에게). 수정: onClaim 에서 SEEN 도 기록.
4. **rw 가 기기(device_id)와 무관하게 시즌만 기록** — myhero.js:27, rewards.js:200-203. 같은 브라우저에서 device_id 가 바뀌면(카카오 adoptPlayer ui.js:756, import) 새 device 의 같은 시즌 pending 이 "이미 지급"으로 판정돼 지급 없이 ack 된다. 드묾(두 기록 모두 순위권일 때만). 수정: rw 항목을 `"dev:season"` 또는 `{d,s}` 로.
5. **옛 탭(v9 myhero.js)이 rw 를 지움** — 옛 load() 는 rw 를 모르고 save 시 버린다. ack 성공 뒤면 서버가 막아 무해, ack 실패+옛 탭 저장이 겹치면 재지급. 허용 가능한 위험으로 문서화만.
6. **CALL_KEY 비교 기준 불일치** — rewards.js:193-194 는 클라 시계의 `phaseNow().season.id`, 206 은 서버 `m.cur` 를 저장. 시계가 어긋나거나 `season` 이 null 인 구간이면 홈 진입마다 서버 호출(read 한도 20/기기를 profile 과 공유). 구 서버(bad_action)일 때도 CALL 을 안 찍어 매번 호출. 수정: unsupported 응답이면 세션 메모리 플래그로 재호출 억제.
7. **rewardAck 20개 상한** — index.ts:107. stale ack 는 pending 전 시즌을 한 번에 보낸다. 20주 넘게 미수령이면 400 bad_seasons 로 영원히 실패. 클라에서 20개씩 잘라 보내기.
8. **MyHero 구버전 혼재 시 거짓 "받았어요!"** — onClaim 에서 `MH.grantReward` 가 없으면 throw→catch→r=0 이지만 done=true 로 완료 화면. 서버 ack 는 안 나가 손실은 없음. `typeof MH.grantReward !== "function"` 이면 open 하지 않기.
9. **랭킹 칩이 구 서버에서도 노출** — ui.js:1170. 서버 배포 전 클라만 나가면 받을 수 없는 보상을 안내. 같은 시점 배포라면 무시 가능. (m 을 한 번이라도 받았을 때만 칩 표시도 가능.)
10. 문구: `<h3>시즌 2 1~3위</h3>`(97·103행)는 숫자가 붙어 읽기 어색 → "시즌 2 TOP 3" 또는 "지난 주 1~3위". 칩의 `aria-label` 이 div(역할 없음)에 붙어 내용 대신 읽히지 않을 수 있음(사소). 코인은 스펙 칩의 🪙 대신 `.coin` C 아이콘 — 디자인 원칙(코인 C 아이콘)과 일치하므로 올바른 선택, 스펙 문구만 갱신 권장. 해요체 일관, 리그명 "운빨 리그/내 영웅 리그" 는 RK_LEAGUE(ui.js:1024)와 일치.
