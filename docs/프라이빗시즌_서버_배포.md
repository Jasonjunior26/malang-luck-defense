# 프라이빗 시즌 서버 배포

순서가 중요하다: DB(마이그레이션) -> 함수 -> 클라이언트.

1. 선행 확인: 002, 003 마이그레이션이 이미 적용돼 있어야 한다(003 의 `players.user_id` 를 닉네임 조회에 사용).
2. DB: Supabase SQL Editor 에 `supabase/migrations/004_private_seasons.sql` 전체를 붙여넣고 Run (재실행 안전).
   - 확인: `select count(*) from private_seasons;` 이 0 으로 나오면 성공. 에러가 나면 `scores` 의 기존 check 이름과 충돌했는지 확인.
3. 함수: `node tools/build_engine.js` (engine.js 에 validateRules/rulesHash 포함) -> `node tools/test_private.mjs && node tools/test_function.mjs` 통과 확인 -> `supabase functions deploy submit-score --no-verify-jwt`.
4. 클라이언트(GitHub Pages) 배포는 함수 배포 이후.
5. 동작 확인(로그인 JWT 필요): `POST /functions/v1/submit-score` body `{"action":"psList"}` + `Authorization: Bearer <JWT>` -> `{"ok":true,"seasons":[]}`.

## 운영 메모
- 액션: psCreate psJoin psGet psList psBoard psKick psCancel psSubmit (모두 JWT 필수, device_id 불필요).
- 호스트 탈퇴(계정 삭제) 시 `select private_season_owner_left('<user uuid>', current_date_kst);` 호출: 가장 먼저 참가한 멤버에게 위임, 멤버 없으면 취소/종료.
- 규칙(rules)이나 ENGINE_VER 를 바꾸면 기존 시즌의 재생 결과가 달라질 수 있으니 진행 중 시즌이 없을 때 배포한다.

## 롤백
- 함수: 이전 커밋으로 되돌려 `supabase functions deploy submit-score --no-verify-jwt` (ps* 가 없어도 기존 액션은 영향 없음).
- DB(프라이빗 시즌 전체 제거, 데이터 삭제 주의):
  ```sql
  drop table if exists public.season_members, public.private_seasons cascade;
  delete from public.scores where mode = 'private';
  alter table public.scores drop column if exists season_id;
  drop function if exists public.submit_score_private, public.private_season_create, public.private_season_join, public.private_season_get,
    public.private_season_list_mine, public.private_season_leaderboard, public.private_season_kick, public.private_season_cancel,
    public.private_season_owner_left, public.ps_json, public.ps_live, public.ps_code, public.ps_counts, public.ps_display_name;
  -- scores 의 완화된 check 는 그대로 둬도 무해(기존 데이터와 호환). 원복하려면 mode in ('daily','practice'), round<=50, score<=30000 로 다시 추가.
  ```
