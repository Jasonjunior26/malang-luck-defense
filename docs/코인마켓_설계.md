# 코인 마켓 설계 (운빨 진열대 + 코인 획득 경로)

## 요약 (결론)
1. 마켓은 **판이 끝날 때마다 새 진열**(기본 5칸, 약 6%로 6칸, 10번째 방문마다 도장 칸). 진열은 방문 단위로 저장해 F5 재추첨 불가.
2. 희귀도 칸당 확률: 커먼 55 / 레어 28 / 유니크 12 / 히든 4 / 에픽 1 (%). 품목 30종, 카테고리 7개.
3. 피티: 유니크+ 없는 방문 3연속 -> 다음 방문 1칸 보장, 히든+ 10연속, 에픽 30연속(시뮬 평균: 유니크+ 1.6방문, 히든+ 3.9, 에픽 14.5, 최악 31).
4. 새로고침: 하루 무료 1회, 그 뒤 방문당 20 / 40 / 80 / 160 코인. 이벤트: 특가 10%, 대박세일 2%, 수상한 상인(비공개 상자 3칸) 3%.
5. 코인 획득: 현행 정산식(코인=라운드·처치·클리어)은 **그대로 두고** 운 층을 얹는다(보스 코인주머니, 황금 몹, 첫 등급 보너스) + 하루 첫 판 +20%, 주간 도장, 신기록, 업적. 판당 캐주얼 약 60 / 보통 약 90.
6. 풀 강화(단계 10 + 조각 28개 + 유니크 각인) 영웅 1종: 캐주얼 약 48판, 보통 약 32판. 3종 전부는 캐주얼 약 137판 / 보통 약 88판(장기 목표).
7. 공정성: 마켓 최종 능력치 상한 공격 +20%(단계 +15% 포함, 서버 검증 한도 1.22), 보상 +23%, 공업 할인 최대 -14%. 서버는 구매를 검증 못 함(사용자 결정 1: 감수) -> 상한이 곧 최악의 경우.
8. 코인은 랭킹 점수에 직접 영향 없음. 시즌 보상도 순위 구간별 지급(클라이언트 장부), 강화 상한 안에서만 점수에 영향.
9. 필요한 새 서버 변경: `validateMine` 확장(pc/eng/bo), 마이그레이션 008(내 기록에 hero_name), 프라이빗 시즌 `mine` 허용.
10. 시뮬: `node tools/market_sim.mjs` (전체 약 5분, `--quick` N=3000, `--e` 수입 경로만 즉시).

## 0. 전제와 기존 구현과의 정합 (docs/내영웅_진행.md, myhero.js, data.js MYHERO 구간)
- 영웅 3종까지 등록, 이름 변경/삭제 없음(사용자 결정 3). 영웅별 `up:{atk,rew,disc,start}`, 단계 비용 `[60,100,160,240,340]`, 총합 10단계 상한. **이 단계 강화는 그대로 두고** 마켓이 위에 얹힌다(대체하지 않음).
- 정산식: `coinsFor = floor((max(0,R-9) + floor(kills/50) + 클리어30) x (1+0.05 x rew단계))`. 프라이빗 시즌 0 (현행).
- 지원되는 fx 키(game.js 확인): startMin upCost sellMul drawCost atkMul(77줄) killMul(434) killLuck(436) bossBonus bossDmg(101) bossTime(224) burnDur slowPlus(105) mobSlow(244) roundMin(233) roundHidden(234) mergeTwin(359) mergeMin(358) interest drawBonus, probMod:"lucky"(data.js 283).
- 용어는 기존 '운' 어휘(등급 커먼~패런츠, 선택권, 뽑기)를 따른다. 마켓 희귀도 5단계 = 기존 GRADES 색 재사용(커먼 #aab6c4, 레어 #3b9dff, 유니크 #a75bff, 히든 #ff8a1f, 에픽 #ff3d7f).

## 2. 진열 규칙
### 2.1 방문 정의와 칸 수
- **방문** = 마지막 진열 생성 뒤 판이 1번 이상 끝났거나 6시간이 지난 뒤의 첫 입장. 같은 방문 안에서 닫았다 열기·F5는 같은 진열.
- 기본 5칸. 이벤트 방문: 보너스칸 6%(6칸), 특가 10%(무작위 1칸 -40%), 대박세일 2%(전 품목 -20%), 수상한 상인 3%(상자 3칸), 평범 79%. **단골 도장**: 방문 10번째마다 6번째 칸(레어 28/유니크 12/히든 4/에픽 1 비율, 레어 이상 보장).
- 수상한 상인: 내용물 비공개 상자 3개, 희귀도 확률 레어 30/유니크 40/히든 22/에픽 8, 가격은 정가의 85%(열어봐야 앎). 시뮬은 내용 공개로 근사.

### 2.2 확률
칸당 희귀도: 커먼 55 / 레어 28 / 유니크 12 / 히든 4 / 에픽 1 (%).
카테고리 가중치(희귀도를 뽑은 뒤 그 희귀도에 있는 카테고리끼리 재정규화): 조각 24, 부스터 18, 강화권 14, 각인 14, 도박 12, 꾸미기 12, 환급 6. 같은 카테고리 안에서는 균등.
- 중복: 한 진열에 같은 품목 2개 불가.
- 필터: 등록 영웅이 없으면 영웅 한정 품목 제외(부스터·도박·환급만). 영웅 한정 품목은 쓸 수 있는 영웅(조각 상한 미만, 같거나 높은 각인 없음, 단계 10 미만)만 대상 후보. 대상 후보가 없으면 그 품목은 제외. 예외 필터: 럭키 고양이에게 행운 부적 제외, 너굴에게 행운 각인(killLuck 고유) 제외.
- 하위 희귀도 폴백: 해당 희귀도에 유효 품목이 없으면 한 단계 아래에서 뽑음.

### 2.3 피티 (나쁜 운 방지)
방문마다(새로고침 제외) 카운터 증가, 해당 등급 이상이 진열에 나오면 0으로 리셋(구매 여부 무관).
- 유니크+ 없음 3방문 연속 -> 다음 방문 무작위 1칸을 유니크+(12:4:1)로 교체
- 히든+ 없음 10방문 연속 -> 1칸 히든+(4:1)로 교체
- 에픽 없음 30방문 연속 -> 1칸 에픽
- 피티 칸에는 작은 라벨 "오늘은 행운의 날" (연출은 5절).

### 2.4 새로고침
- 하루(KST) 무료 1회: "오늘의 무료 둘러보기". 이후 방문당 20 -> 40 -> 80 -> 160(이후 160 고정). 새 방문이 오면 비용 단계 초기화.
- 새로고침은 같은 방문의 이벤트를 유지한 채 칸만 다시 굴림(남은 칸 모두 교체, 이미 산 칸은 품절 표시). 피티 카운터는 올리지 않음(리롤 반복으로 피티를 빨리 채우는 것 방지), 단 희귀 등장 시 리셋.
- 새로고침 무료권(#15)은 가장 비싼 단계를 한 번 깎는 용도.

### 2.5 한정감 / 긴장감
- 모든 품목은 그 방문에서만 판매. 히든+ 칸에는 "다시 나올까?" 문구, 사지 않고 나가면 도감 "놓친 보물" 줄에 마지막 놓친 히든+ 1건 기록.
- 시즌 한정 꾸미기(이름 장식)는 시즌 기간에만 유니크 칸 후보에 합류(SEASONS 사용).
- 품절: 산 칸은 "품절" 도장. 재고 부족 이벤트는 만들지 않음(나쁜 경험이라 판단).

### 2.6 시드와 저장 (F5 방지)
- 방문 생성 시 랜덤 `seed`(32비트)를 한 번 뽑아 저장, 진열 = f(seed, rerollIdx) 의 결정론적 난수(mulberry32). F5, 탭 재오픈은 같은 값을 재현. 새로고침은 rerollIdx 증가를 저장한 뒤에만 결과를 보여 줌(저장 전 중단해도 결과가 같음).
- 구매는 즉시 저장(`sold` 배열). 한계: 로컬스토리지라 직접 편집은 가능(사용자 결정 1에 따라 감수; 서버는 강화 상한만 방어).

저장 스키마 (키 `malang-market`, 기존 `malang-myhero` 와 별도):

  "rerollsThisVisit": 1, "stamp": 7, "lastMissed": { "id": "eng_luck", "visit": 35 },

## 5. 코인 획득 경로 설계 (가장 중요한 추가 과제)
원칙: (1) 서버에 코인 장부가 없으므로 모든 수입은 클라이언트 신뢰 기반이며 **코인은 점수 공식에 들어가지 않는다**. 코인이 랭킹에 영향을 주는 길은 강화 상한(3.4)뿐이라 코인을 무한히 속여도 최악은 상한 값이다. (2) 현행 `coinsFor`·단계 비용은 그대로. (3) 강요(스트릭 손실)가 없는 보너스만.

### 5.1 판 종료 정산 다듬기
기본(현행 유지): 라운드 도달 max(0,R-9) + 처치 floor(kills/50) + 클리어 30, x(1+5% x rew단계).
- 보스 처치: 보스 1기마다 코인 주머니(5.2) 굴림. 라운드 도달 항에 이미 포함되므로 별도 고정치는 없음.
- 내 영웅 출전 +5%, 신기록 보너스: 영웅별 최고 라운드 갱신 시 갱신 라운드 수 x2 (최대 20, 첫 판은 0).
- 판당 최대 코인 상한 250(조작 클라이언트 방어는 못 하지만 UI 이상치 방지).
### 5.2 판 중 코인이 터지는 순간 (말랑 럭키 톤)
별도 난수 스트림 `S.rng.coin`(시드에서 파생, 기존 gacha/misc 스트림은 소비하지 않아 기존 판 재현에 영향 없음). 판 결과 `coinFx` 합계를 정산에 더함. **서버 재현 점수는 영향 없음**(코인 합계는 서버가 검증하지 않음).

## 6. 구현 인수 사항
### 6.1 단계 강화와의 합치기 (권장안)
**보완안**: 단계 강화(공격/보상/할인/시작)는 "기본 길", 마켓은 "운 길". 마켓 품목이 단계를 대체하지 않고 같은 방향에 조각이 +α, 각인은 새 효과, 강화권/방향지정권은 단계 구매를 돕는 쿠폰으로 쓰인다. 단계 UI 는 그대로, 영웅 화면에 "조각 N/6, 각인" 줄만 추가.
### 6.2 새 fx / game.js 적용 위치
| 필요 | 위치 | 내용 |
|---|---|---|
| `applyMine` 확장 | data.js MYHERO 구간 | pc -> atkMul(1+0.005xN) killMul upCost startMin(+2xN), eng -> 위 표의 fx, 영웅 고유 fx 와 병합(수치 가산, 확률은 max) |
| `fx.probMod` 값 1.5 | data.js gradeProbs(283줄) | lucky 와 별도 배율 |
| 부스터 | 판 시작(mine.bo) | startMin / drawCost / probMod 에 가산, 소비는 판 종료 정산에서 |
| `S.rng.coin` + `coinFx` | game.js newGame / killMob / 뽑기 | 보스 주머니, 황금 몹, 첫 등급 |
| 정산식 | data.js coinsFor / myhero.js settle | 운 층·신기록·일일·주간 |
| 새로고침 등 | 새 파일 market.js | 진열 생성(시뮬과 동일한 로직), UI, 저장 |
| drawCost 하한 | game.js 39행 근처 | 프라이빗 규칙 drawCost 와 영웅/부스터 할인이 겹치면 최소 8 로 클램프 |
### 6.3 서버 영향
- `validateMine` 확장: `mine = {hero, up, pc:{atk,rew,disc,start}, eng:id|null, bo:id|null}`. 허용 id 화이트리스트, 조각 상한(6/6/4/6), 상한 초과 시 거부. 코인 조각·코인 리본·꾸미기·강화권·복권은 mine 에 넣지 않음(점수 무관).
- 구매 검증 불가는 사용자 결정 1에 따라 감수. 서버는 상한 안의 모든 조합을 합법으로 본다.
- 재생 일치는 기존대로(seed+inputs+mine). `S.rng.coin` 은 별도 스트림이라 점수에 영향 없음.
### 6.4 프라이빗 시즌에서 내 영웅 허용 (사용자 결정 4)
- private.ts 가 mine 을 받아 submit_score_private 재생에 전달. 시즌 생성 시 호스트 옵션 `allowMine`(기본 true)과 `mineCap`(100%/50%/0%, **기본 50%** — 사용자 확정, 호스트가 변경 가능).
- 규칙 모디파이어와의 상호작용: `heroPool` 이 있으면 mine.hero 가 풀에 속할 때만 허용. `startMin` 규칙 + 단계/조각 시작 미네랄은 가산(규칙 상한 200 유지). `drawCost` 규칙(10~25) - 영웅/부스터 할인은 최소 8 클램프. `luckyWeek` 켜짐이면 행운 부적 무효. `killReward` 규칙 x 보상 강화는 곱(최대 2 x 1.25 = 2.5). `noSell/noGrade/gradeCap/drawLimit/clanBan/hpMul/mobSpeed/mobCount/bossTime/rounds` 는 그대로 적용되고 강화는 그 위에 얹힘.
