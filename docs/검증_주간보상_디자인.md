# 주간 랭킹 보상 UI 디자인 검증 (독립 검증, 2026-11-10)

대상: `Quick-game-wr` 브랜치 feat/weekly-rewards(미커밋). rewards.js(19:51 수정본), index.html(19:36) rw* CSS(225~241줄).
검증 중에도 작성자가 rewards.js 를 고치고 있었습니다(h3 "1~3위" → "TOP 3"). 아래 줄 번호는 19:51 기준입니다.

## 방법
- Chrome 확장: 탭이 응답하지 않아(javascript_tool·screenshot 3회 연속 타임아웃) 중단했습니다.
- 대체 방법: Playwright(Python, headless Chromium)로 `localhost:8765`(워크트리와 md5 일치 확인)에 접속했습니다. 서비스워커를 차단해 캐시 문제를 배제했고, `prefers-color-scheme` 을 에뮬레이션해 라이트·다크를 모두 봤습니다. 닉네임 모달이 먼저 뜨지 않게 `malang-name`/`malang-name-ok` 을 미리 넣고 외부 요청은 차단했습니다.
- 범위 행 DOM 텍스트: demo1 `C 150 ~ 10` / `C 140 ~ 10`, demo3 `C 140 ~ 10`. 물결표 반영을 확인했습니다.

## 확정 결함

### 차단
1. **320px 에서 보상표가 17px 넘쳐 오른쪽 열이 잘립니다**(두 리그 열이 따로 나오는 demo1·2). 스크린샷에서 "140 ~ 1" 까지만 보입니다.
   - 원인: `index.html:234` 의 칸 패딩 `var(--s2) var(--s3)`(좌우 12)에 `:236` 의 `tbody th { white-space:nowrap }` 이 겹쳐 최소 폭이 커집니다.
   - 수정안:
     ```css
     .rwt th, .rwt td { padding:var(--s2); }
     .rwt tbody th { padding-left:var(--s3); }
     .rwt tbody td { padding-left:0; padding-right:var(--s2); }
     ```
     줄인 패딩으로 칸마다 4~12px 를 회수하면 최소 21px 이 생깁니다.
   - 또는 열이 2개일 때 표 글자를 `--fs-body` 로 낮추고, `보너스 +200` 줄을 1위 행에만 남깁니다.

### 중요
2. **보상표 머리 줄 왼쪽 빈칸에 흰 막대가 보입니다**(라이트·다크 모두). `rewards.js:92` 의 `<td></td>` 에 `index.html:234` 의 `background:var(--surface)` 가 적용되고, `:235` 는 `thead th` 만 투명으로 되돌리기 때문입니다.
   - 수정: `.rwt thead td, .rwt thead th { background:none; padding:0 var(--s2); }`
3. **안내문(.rwhint)과 도전 문구(.rwgo) 위아래에 24px 여백이 붙어 리듬이 깨집니다.** `index.html:208` 의 `.rkl > p { margin:24u 0 }`(특이도 0,1,1)이 `.rwhint`/`.rwgo`(0,1,0)의 margin 을 이깁니다. 화면에서 "보상표" 제목과 안내문 사이, 표 아래가 크게 비어 보입니다.
   - 수정: `.rwp .rwhint{margin:var(--s1) 0 var(--s2)} .rwp .rwgo{margin:var(--s2) 0 var(--s3)}`. 또는 rwhint 를 `<small class="rwhint">`(display:block)로 바꿉니다.
4. **랭킹 칩에서 띄어쓰기가 사라집니다**: "1위C 400· 상위 30%까지"(확대 화면으로 확인). `index.html:241` 의 `display:flex` 때문에 텍스트 노드 끝의 공백이 접히고, `text-overflow:ellipsis` 도 flex 에서는 동작하지 않습니다.
   - 수정: `display:block; text-align:center;`(나머지는 유지). 세로 정렬은 `.coin` 의 inline-flex 가 맡습니다.
5. **받은 뒤 화면이 서로 어긋날 수 있습니다**: `got===0` 이면 "이미 받았어요" 아래에 큰 글씨 `C 0` 이 나오고, 바로 아래 `+400 / +210` 줄이 그대로 남습니다(`rewards.js:102,105`).
   - demo 의 `onClaim: () => 0`(`rewards.js:200`) 때문에 **데모로는 "받았어요!" 성공 화면을 볼 수 없습니다.** 실제로 1회 클릭 후 측정한 값: "이미 받았어요 / C 0 / 운빨 리그 1위 / +400".
   - 수정:
     - demo onClaim 은 `(c) => c.reduce((a,p)=>a+p.total,0)` 을 반환합니다.
     - got===0 이면 큰 금액 대신 `claim` 합계를 흐리게 보여 주거나 `.rwamt` 를 숨깁니다.
6. **명도 대비 미달(텍스트 4.5:1 기준).** 측정값입니다.
   - 라이트:
     - 캡션 글자 opacity .55~.7 → 2.97~4.12
       - `.rs` 2.97
       - `.rwhint`/`.rwsub`/`.rwlg>small` 3.55~3.8
       - `thead th` 4.12
     - 분홍 금액 `.sc`(--pink2 #e0558a) → 흰 바탕 3.6, hl 바탕 3.13
   - 다크: 분홍 금액이 li.me(hl) 위에서 **2.78**(UI 3:1 도 미달), surface 위에서 3.29
   - 기존 랭킹 화면에서 물려받은 패턴이 대부분이지만 이 팝업에서 새로 늘어났습니다.
   - 수정안:
     - 투명도 대신 색 토큰을 씁니다: `.rwsub,.rwhint,.rwlg>small,.rwt thead th,.rwt tbody th small{opacity:1;color:var(--mute)}`. mute 는 라이트 card 위 5.27, 다크는 충분합니다.
     - `.rwp .rows .sc{color:var(--pink-deep)}`. 라이트 흰 바탕 6.26, hl 바탕 5.45이고, 다크는 #f3a0bf 로 바뀝니다.
7. **'보상 없음' 블록 문장이 어색하게 줄바꿈됩니다.** 360px 에서 "상위 30%까지 보상을 받아요 (운빨 / 리그 11위 · 내 영웅 리그 10위까지)" 처럼 리그 이름이 둘로 갈립니다. 괄호도 원칙 §25(괄호 줄이기)에 어긋납니다(`rewards.js:106,115-118`).
   - 수정: 줄을 나눕니다(§26).
     ```html
     <b>이번엔 보상이 없어요</b>
     <p>운빨 리그 <b>11위</b> · 내 영웅 리그 <b>10위</b>까지 받아요</p>
     <p>다음 주엔 꼭 받아 가요!</p>
     ```
     리그 이름마다 `<span class="rwn">` 로 줄바꿈을 막습니다. "상위 30%" 는 표의 범위 행에 이미 있으니 뺍니다.

## 의심과 '구림' 소견 (사소)
- **포인트 색 hl 이 한 화면에 세 가지 뜻으로 쓰입니다**: 내 보상 블록, 내 줄(li.me), 표 1위 행. 원칙 §0-2 '포인트 색은 화면당 1~2개'에 걸립니다.
  - 제안: 표 1위 행은 `background:var(--surface)` 에 금색 왼쪽 막대와 18px 굵기만 남깁니다. 라이트에서 금색 막대와 hl 의 대비가 1.52라 지금은 막대가 거의 보이지 않습니다.
- **같은 코인 금액이 세 가지 모양으로 나옵니다**: 내 보상 줄 `+400`(분홍, 아이콘 없음), TOP 3 `C 400`(분홍), 표 `C 400`(먹색 800). 표·내 보상을 먹색과 아이콘으로 통일하면 정돈됩니다.
- **4위~ 범위 행 배경(--card2)이 모달 그라디언트 바닥색과 같습니다**(대비 1.05). 그래서 칸이 아닌 빈 줄처럼 보입니다. `background:var(--neutral)` 또는 `var(--surface)` 에 `opacity:.85` 를 쓰는 편이 낫습니다.
- **"상위 30%" 가 한 화면에 3~4번 반복됩니다**(보상 없음 블록, 표 위 안내, 표 범위 행). 표 아래 "순위가 높을수록…" 도 표가 이미 보여 주는 내용입니다.
  - 제안: 표 위 안내는 "리그별로 따로 받아요" 만 남기고, 표 아래 안내는 삭제합니다.
- **제목 "시즌 2 TOP 3" 의 영문 혼용**: 용어 통일(§11) 관점에서 "시즌 2 1~3위" 나 "지난 주 1~3위" 가 앱 말투와 맞습니다.
- **섹션 제목(h3) 13px 이 리그 소제목 12px 과 거의 같아 위계가 약합니다.** `.rwp h3{font-size:var(--fs-strong);font-weight:800}` 을 제안합니다.
- **오류 문구가 캡션 스타일입니다**: 오류 문구 `p.rwhint role=alert` 가 흐린 12px 캡션이라 눈에 띄지 않고, 3번의 24px 여백도 붙습니다. `color:var(--danger)`, `opacity:1` 을 권합니다.
- 칩의 `aria-label`(div, role 없음)은 스크린리더가 무시합니다. 빼도 됩니다.
- Tab 을 버튼에 가둬서 키보드 사용자는 긴 본문을 Tab 으로 스크롤할 수 없습니다. 방향키나 휠은 됩니다. 영향은 작습니다.

## 문제없음
- 토큰만 사용, 버튼 위계(Primary 1개, 스크롤 밖 하단 고정), 터치 44px 이상(47/56/70).
- --u 태블릿 스케일, 가로 문서 넘침 0, 범위 행 물결표, .coin 과 숫자 줄바꿈 방지(.rwn), reduced-motion(새 모션 없음).
- 다크에서 보상표 1위 강조는 충분합니다(금색 막대와 hl 대비 5.72).
