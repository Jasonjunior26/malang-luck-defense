# 말랑 디펜스 소셜 기획안 (사용자 관점)

2026-10-30. 개발 설계는 `docs/소셜_시즌_설계안.md` (이하 "설계 §N"). 여기서는 누가·왜·어떻게 쓰는지만 다룬다.

## 0. 현재 UX 기준점
- 타이틀: 시즌 박스(공식 시즌·1위·내 순위·닉네임 칩) / 오늘의 히어로 / [일일 챌린지] [연습 모드] [랭킹 보기].
- 닉네임: 첫 실행 시 모달(2~10자, 하루 1회 변경, 이전 코드 가져오기).
- 랭킹: 모달, 탭 시즌 TOP50 / 오늘 / 내 기록. 공식 시즌은 하드코딩, 모두 같은 규칙.

## 1. 핵심 목표와 시나리오
**목표:** 혼자 하는 운빨 게임을 "지인과 같은 규칙으로 겨루는 일주일"로 바꿔 재방문을 만든다.
| 사용자 | 왜 쓰나 | 필요한 것 |
|---|---|---|
| 솔로 | 기록 갱신, 공식 시즌 순위 | 로그인 없이 플레이, 기록 보존 |
| 호스트 | 지인끼리 판 벌이기 | 쉬운 시즌 생성, 한 번에 초대 |
| 참가자 | 링크 눌러 바로 합류 | 가입 마찰 최소, 규칙이 한눈에 |

**시나리오**
1. **일주일 하드코어:** 호스트가 "하드코어" 프리셋으로 7일 시즌 생성, 카톡 단톡방에 링크 전송. 친구 5명이 합류, 매일 최고점 경쟁, 마지막 날 우승자 카드 공유.
2. **점심 내기 하루 시즌:** 사무실 8명이 "운빨 파티" 1일 시즌. 퇴근 전 순위로 커피 내기.
3. **솔로의 확장:** 게스트로 하던 유저가 공식 시즌 상위권에 들자 로그인, 친구 추가로 친구 탭 순위를 본다.

## 2. 사용자 흐름
### ① 초대 링크 받은 신규 유저
1. 카톡에서 시즌 초대 카드 탭 → 초대 수락 화면 (시즌 이름·규칙 칩·참가자 수, 로그인 불필요하게 미리보기).
2. [참가하기] → 카카오 로그인 (동의: 닉네임/프로필).
3. 닉네임 확인 (카카오 닉네임 제안, 수정 가능, 충돌 시 §5).
4. 시즌 참가 완료 → 시즌 상세로 이동, 규칙 칩 확인.
5. [시작] → 시즌 규칙으로 첫 판 (첫 판 한정 토스트 1회).
6. 게임오버 → 점수·시즌 순위 표시 → [카톡 공유] / [다시 하기].

### ② 기존 게스트의 기록 계정 연결
1. 랭킹 등록·친구·시즌 참가 중 하나를 누르면 로그인 유도 시트.
2. 카카오 로그인 완료 → "이 기기 기록 N개를 연결할까요?" (기본 선택됨).
3. 연결하면 기존 닉네임·최고 기록이 계정으로 이동. 이후 다른 기기에서도 로그인으로 복구.
4. 건너뛰기(나중에) 가능. 기기 기록은 그대로 남는다.

### ③ 시즌 만들기 (호스트)
1. 타이틀 [시즌] → [+ 시즌 만들기].
2. 프리셋 선택 (6종 + 직접 구성).
3. 모디파이어 조정 (최대 3개, 칩 on/off + 슬라이더).
4. 이름·기간(시작일·종료일)·최대 인원 입력.
5. [만들기] → 초대 화면: [카톡으로 초대] [링크 복사] [코드 보기].
6. 시작일 전에는 "대기" 상태. 규칙 수정 가능, 시작 후 불가.

### ④ 친구 추가
1. [친구] → 내 코드(`닉네임#1234`) + [내 링크 공유] + 코드 입력칸.
2. 코드 입력 또는 링크 탭 → 요청 전송.
3. 상대는 친구 탭 배지에서 [수락]/[거절].
4. 수락되면 친구 목록에 최고 기록 표시, 랭킹 "친구" 탭 활성.

### ⑤ 시즌 종료·우승
1. 종료일 자정(KST) 제출 마감, 순위 확정.
2. 다음 접속 시 결과 팝업: 최종 순위·우승자·내 기록.
3. 우승자 칩이 프로필에 남고 [우승 카드 공유] 제공.
4. 시즌은 "지난 시즌" 목록으로 이동, 순위 열람 영구 보관.
5. 호스트에게 [같은 규칙으로 다시 열기] 제안.

## 4. 시즌 운영 규칙 (제안안)
| 항목 | 제안안 | 근거 |
|---|---|---|
| 중도 참가 | 종료 전까지 언제든 가능, 이미 지난 기간 소급 없음 | 늦게 온 친구도 최고점 경쟁에 바로 합류 |
| 호스트 권한 | 초대, 내보내기, 취소, 이름 변경. 규칙은 시작 전만 변경, 시작 후 불가 | 공정성 + 서버 재생 검증 일관성 |
| 시즌 취소 | 시작 전 자유, 시작 후는 참가자 2명 이상이면 불가 (종료만 가능: 호스트가 [조기 종료]) | 참가자 기록 보호 |
| 내보내기 | 호스트 가능, 해당 유저 기록은 순위에서 제외, 재입장 차단 | 어뷰저 대응 |
| 판수 제한 | 기본 무제한, 호스트가 하루 N판(3/5/10/무제한) 선택 | 열정형·가볍게형 모두 수용 |
| 순위 기준 | 시즌 내 최고점 1개 | 운빨 게임이라 평균은 편차만 키움 |
| 동점 | 도달 라운드 → 먼저 달성한 시각 | 먼저 한 사람이 우위, 단순 |
| 종료 후 | 순위 영구 열람(읽기 전용), 우승 칩 프로필 영구 | 자랑거리 유지 |
| 인원 상한 | 기본 10, 최대 30 (공개 확장 시 상향) | 지인 규모, 서버 재생 비용 |
| 계정당 시즌 | 진행+대기 3개 참가 / 호스트는 그중 2개 | 설계 §4 (생성 한도는 참가의 부분집합) |

## 5. 예외·엣지 케이스
| 상황 | 처리 |
|---|---|
| 로그아웃 상태로 초대 링크 | 초대 수락 화면(G)은 미리보기 허용, [참가하기]에서 로그인 → 자동 참가로 복귀 |
| 이미 참가한 시즌 | 시즌 상세로 바로 이동, "이미 참가 중이에요" 토스트 |
| 정원 초과 | "자리가 다 찼어요" + 구경하기(순위 열람 불가, 이름만), 호스트에게 정원 확대 요청 버튼 |
| 종료 후 링크 | 읽기 전용 최종 순위 + [같은 규칙으로 새 시즌 열기] |
| 닉네임 충돌 | 코드(#1234)로 구분, 표시는 닉네임만, 같은 시즌 내 동명이면 #코드 병기 |
| 카카오 연동 실패/취소 | 게스트 상태 유지, "로그인에 실패했어요" + [다시 시도]. 게임은 막지 않음 |
| 오프라인 제출 | 기기에 큐 저장 → 온라인 복귀 시 자동 전송, 마감 후 도착분은 "기간 밖" 처리 |
| 마감 직전 판 | 시작 시각 기준 인정(판 시작이 기간 내면 유효), 제출은 +10분 유예 |

## 6. 공유 콘텐츠
카톡 피드 카드 = 이미지 + 제목 + 설명 + 버튼. 문구는 한 줄씩.

| 종류 | 이미지 | 제목 | 설명 | 버튼 |
|---|---|---|---|---|
| 게임오버 | 최종 보드 캡처, 점수 | "R45 · 9,400점!" | "금요 하드코어 3위. 이 기록 넘어봐" | [나도 도전] |
| 시즌 초대 | 규칙 칩 모음 + 호스트 캐릭터 | "하늘님의 하드코어 시즌" | "11/1~11/7 · 체력×1.8 · 6/10명" | [참가하기] |
| 시즌 우승 | 왕관 + 우승자 | "👑 금요 하드코어 우승" | "12,300점 · 6명 중 1위" | [나도 도전] |

**초대 링크 동작** (`/?season=코드`, `/?friend=코드`)
1. 앱 설치됨 → 앱/브라우저에서 열고 초대 수락 화면(G).
2. 미설치 → 웹 PWA로 열기. 홈 화면 추가는 첫 판 끝난 뒤 한 번만 권유.
3. 코드는 URL에서 읽은 즉시 보관하고 주소창에서 지움.
4. 링크 오용 방지: 시즌 코드는 호스트가 재발급 가능 (구 코드 무효).
5. 카톡 불가 환경 → 링크 복사, Web Share.

## 7. 성공 지표
초기 목표는 지인 수십 명 기준. 모두 Supabase SQL로 산출.

| 지표 | 정의 | 측정 |
|---|---|---|
| 가입 전환율 | 로그인 유도 노출 대비 로그인 완료 | 클라 이벤트 `login_prompt`/`login_ok` 테이블 집계 |
| 초대→가입 전환 | 초대 링크 오픈 수 대비 신규 가입 후 참가 | `invite_events(open)` vs `season_members.joined_via=invite` |
| 시즌 생성 수 | 주간 신규 `private_seasons` | `count(*) group by week(created_at)` |
| 시즌당 평균 참가자 | 시즌별 멤버 수 평균 | `avg(cnt)` from `season_members group by season_id` |
| 7일 재방문 | 가입 후 7일 내 다시 제출한 비율 | `scores.created_at` 가입일+1~7일 존재 여부 |

목표 예시(첫 4주): 초대→가입 40%, 시즌당 평균 4명, 7일 재방문 35%.

## 8. 오픈 이슈 / 결정 필요

2026-10-30: 1~5번은 제안안대로 확정. 6~7번은 미정.

| # | 질문 | 제안안 |
|---|---|---|
| 1 | 타이틀 [시작]을 일일 챌린지/연습 2택 시트로 합칠까, 기존 두 버튼을 유지할까? | 합침. 마지막 선택 기억 |
| 2 | 판수 제한 기본값? | 무제한 기본, 호스트 선택 가능 |
| 3 | 동점·순위 기준: 최고점 vs 합산? | 최고점, 동점은 도달 라운드→먼저 달성 |
| 4 | 비로그인 유저의 랭킹 등록 허용 여부? | 로그인 필수 (공식 시즌 포함), 단 기존 기기 기록은 연결 시 이관 |
| 5 | 프라이빗 시즌 인원 상한과 비용 한도? | 기본 10/최대 30, 서버 재생 비용 측정 후 조정 |

| 7 | 공식 시즌과 프라이빗 시즌의 관계? | 공식은 유지, 프라이빗은 별도. 공식은 우승 칩 별도 |
