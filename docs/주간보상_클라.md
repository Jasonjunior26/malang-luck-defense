# 주간 랭킹 보상 - 클라이언트 구현 (에이전트 C, 2026-11-10)

## 변경 파일
rewards.js(신규) / myhero.js / ui.js(3줄) / index.html(CSS 블록·script) / config.js(REWARDS_ENABLED:true) / sw.js(v44-weekly-rewards, SHELL 에 rewards.js) / tools/test_rewards_ui.mjs / docs.

## 저장 구조
`malang-myhero2` 에 `rw:[시즌id...]` 추가(양의 정수·중복 제거·정렬·최대 200개, 손상값은 load 가 정리, 없으면 []). 기존 save 경로는 load() 결과를 그대로 저장하므로 rw 가 보존된다.
별도 키: `malang-rw-seen`(팝업을 본 직전 시즌 id), `malang-rw-call`(그 시즌 처리를 모두 끝낸 현재 시즌 id).
`MyHero.grantReward([{season,total}...])`(또는 `(시즌[], 금액)`)·`MyHero.rewarded()`. 코인+rw 를 한 번의 save. 이미 rw 에 있는 시즌은 0. 시즌당 100000·코인 총량 99999999 상한, 음수·소수·문자열은 0.

## 흐름
홈 진입(initPlayer 뒤, goHome 때)에 `Rewards.boot()`: 닉네임 등록·온라인·판 밖일 때만 서버 `rewards` 호출(시즌당 1회, 처리 완료 시 `rw-call` 기록). pending 중 rw 에 없는 시즌만 [받기] 대상. 받기 -> grantReward -> `rewardAck`(실패해도 재지급 없음; 다음 진입에서 서버 pending 이 다시 오면 팝업 없이 ack 만 재시도). 직전 시즌을 이미 봤고 pending 도 없으면 안 띄움. 404/bad_action/오프라인/예외는 조용히 무시. ESC 로 닫으면 지급 없이 닫히고 다음 진입에 다시 뜬다.
`?rwdemo=1`(보상 있음·두 리그) / `2`(보상 없음) / `3`(한 리그·긴 이름): 가짜 데이터, 서버·저장·코인 변화 없음, 페이지당 1회.

## 화면 구성(랭킹 모달 틀 .rkw/.rkl/.stk 와 .rows 줄 재사용)
제목 "지난 주 랭킹 보상" + 시즌 표기 / (1) 내 보상 블록(수령액 큼직하게 + 리그별 순위·금액) 또는 "이번엔 보상이 없어요 · 상위 30%까지(리그별 k위)" / (2) 두 리그 1~3위(내 닉네임 강조, 영웅명 작게) / (3) 보상표(아래 참고) / (4) 도전 문구 / 하단 고정 주 버튼 1개(받기 -> 받은 뒤 확인). 랭킹 모달의 이번 시즌 순위 탭 상단에 칩 "주간 보상 · 1위 C 400 · 상위 30%까지".

## 보상표 재디자인 (에이전트 D, 2026-11-10)
기존 한 줄 문장을 진짜 표(`table.rwt`)로 교체. 안내 두 줄(위 "리그별로 따로 받아요 · 상위 30%까지 보상", 아래 "순위가 높을수록 …") + 도전 문구 "다음 주엔 내가 1위! C 400을 노려 봐요".
- 열: 리그(운빨 | 내 영웅). 두 리그 k 가 같으면 "두 리그 모두" 한 열, 리그 정보가 없으면 k=10 한 열(머리 없음). 리그별 k 로 totalOf 계산이라 2·3위·범위 행이 열마다 다를 수 있다(1위는 항상 400).
- 행: 1위(--hl 배경 + 금색 왼쪽 띠 + 큰 금액) / 2위 / 3위 / "4위~ 상위 30%"(범위 행, `C 기본액 ~ 최소`, 큰 값 ~ 작은 값, 한 덩어리 nowrap, --card2 배경). 행 머리 밑 작은 글씨로 순위 보너스(+200/+70/+50).
- 서버 tbl(b1,b2,b3,extra1,ratio,last) 사용, 없으면 기본값. 순수 함수 `_t.tableCols/tableRows` 로 테스트.
- 눈 확인: 폭 320/360/390/768, 라이트·다크(다크는 iframe 에 dark 미디어 규칙 주입), 표 scrollWidth==clientWidth, 모든 행 한 줄(48~53px).

### 검증 반영 (docs/검증_주간보상_디자인.md 전 항목)
칸 패딩 --s2(순위 칸만 왼쪽 --s3)로 320px 넘침 해소 / 머리 빈 칸 투명 / `.rwp .rwhint·.rwgo` margin 재지정 / 칩 display:block(공백·말줄임) / 받은 뒤: 지급액 0 이면 "이미 받았어요"만, 지급액이 계획과 다르면 줄별 내역 숨김, 데모 onClaim 은 합계 반환(코인·저장 변화는 없음, 성공 화면을 데모로 볼 수 있음) / 캡션은 opacity 대신 var(--mute), 분홍 금액은 var(--pink-deep)(내 줄 위는 --ink) / 보상 없음: 리그 이름+순위를 nowrap 묶음으로 별도 줄, 괄호 제거 / 제목 "시즌 N 1~3위"(영문 제거), h3 --fs-strong 800 / 1위 행은 surface+금색 띠(노란 hl 은 내 보상 블록·내 줄만), 4위~ 행은 --neutral / 표 아래 안내 삭제, 위 안내는 "리그별로 따로 받아요" / 금액은 모두 .coin 아이콘 + tabular 숫자 / 오류 문구 --danger.
측정(Playwright, 데모 1·2·3 × 320/360/390/768 × 라이트·다크 × 받기 전·후): 가로 넘침 0, 표 폭=칸 폭, 텍스트 대비 모두 4.5 이상, 버튼 47/56px, 표 행 한 줄.

## 통합 검증 결함 수정 (에이전트 E, 2026-11-10; 근거 docs/검증_주간보상_클라통합.md)
- **[중요] 큐잉된 보상 팝업이 판과 겹침**: myhero 의 시작 순서가 `closeModal(); startRun()` 이라 closeModal 시점엔 TITLE_ON 이 아직 true -> 큐의 팝업이 열린 채 판이 시작됐다. 수정: 보상 팝업 go 에 `go.rw=true` 표식, ui.js `dropRwModals()`(큐에서 rw 만 제거)를 myhero 시작 버튼(closeModal 직전)과 `startRun` 첫머리에서 호출, go 안에서도 `TITLE_ON===false` 면 열지 않음. 못 받은 보상은 사라지지 않고 다음 홈 진입(boot)에 다시 뜬다.
- **상태 복구**: `Rewards.reset()`(showing 해제 + keydown 리스너 제거, 단일 진입점)을 goHome 의 강제 정리와 판 재시작 경로에서 호출. 또한 `isShowing()` 이 showing 을 DOM(MODAL_ON, #rwOk)으로 재판정해 누수가 있어도 boot/open 이 자가 복구한다. 팝업 인스턴스 토큰(`inst`)으로 낡은 close/ESC 핸들러는 무시.
- **저장 실패**: `MyHero.grantReward` 가 save 뒤 rw 를 읽어 확인, 실패면 `{granted:0, saved:false}`. 클라는 ack 하지 않고 팝업에 오류 안내(`role=alert`, `.rwhint`)를 띄우며 받기를 다시 누를 수 있다.
- **완료 화면 금액**: 청구 합계 대신 실제 지급액(granted). 0 이면 "이미 받았어요".
- **ack 분할**: 시즌 20개씩 순차 전송(서버 한도), 하나라도 실패하면 실패.
- **SEEN**: 받기 성공 시점에도 기록(확인 전 앱 종료 후 '보상 없어요' 팝업 방지).
- **서버 유예(종료 후 10분, last:null·pending:[])**: `cur>=3 && !last && !pending` 응답은 정산 전으로 보고 팝업·SEEN·CALL_KEY 를 기록하지 않는다(시즌 2 이전엔 원래 last 가 없으므로 cur<3 은 정상 완료). 이전 코드는 이 응답에도 CALL_KEY=cur 를 찍어 그 시즌 내내 재호출이 막혔다. 호출 폭주 방지: 유예 응답 후 최소 5분 간격(`malang-rw-gr`/`-grs`, 시즌 바뀌면 무효), 호출 실패·미지원(구 서버 포함) 후엔 이번 실행에서 60초간 재호출 안 함(메모리), 정산된 응답을 받으면 기존대로 시즌당 1회.
- **기타**: MyHero 에 grantReward 가 없으면(구버전 혼재) 팝업을 열지 않음("nomh"). 제목 "시즌 N 1~3위" -> "시즌 N TOP 3".
- **보류(보고서 사소 4·5·6·9)**: 4(rw 를 device_id 별로) - 저장 구조 변경이라 마이그레이션 필요, 발생이 드묾. 5(옛 탭이 rw 삭제) - ack 성공 시 서버가 막아 무해, 문서화만. 6(CALL_KEY 시계 불일치) - 실패 억제·유예 간격으로 폭주는 막혀 보류. 9(구 서버에서 랭킹 칩 노출) - 서버·클라 동시 배포 전제.
- 테스트: tools/test_rewards_ui.mjs 섹션 7(영웅 선택창 열린 채 응답 도착->시작, 판 중 큐에서 꺼내짐, goHome 상태 복구, 누수 자가 복구, 저장 실패, 이미 받음 표시, ack 분할, 유예 응답 재호출, 서버 미지원 1회, 구 MyHero).
