### A7. 몬스터 HP/방어력 변환식 [신규, 원작 표 기반]

원작 HP는 r1 10 → r47 60,000(6,000배)로 지수 폭증하는데, 우리 플레이어 DPS 곡선은 선형에 가깝다(시뮬: 뽑기 평균 DPS r10 약 870, r30 약 4,000, r50 약 8,900). 그래서 **거듭제곱 압축**한다.

```
hpGame(r) = round( HP_K * origHp(r)^HP_GAMMA * bossEase(r) * earlyEase(r) * finalMul(r) )
HP_K = 11, HP_GAMMA = 0.66
bossEase(r)  = r%5==0 ? min(1, 0.3 + r/50) : 1      // 초반 보스가 DPS 체크로 즉사시키지 않게 (r5 0.4배 ... r35 이후 1배)
earlyEase(r) = min(1, 0.4 + 0.15*r)                  // r1 0.55, r2 0.7, r3 0.85, r4부터 1
finalMul(r)  = r==50 ? 4 : 1                         // 최종 보스는 마지막 DPS 체크
armor%(r)    = round(100*d/(d+40))                   // d = 원본 방어력. 피해 = 공격력 * (1 - armor% * (1 - 방무))
```

- 방어율 예: d=1→2%, 10→20%, 30→43%, 50→56%, 100→71%. 방어 무시(방무 p)는 `armor% x (1-p)`. 별빛무리(방무 0→100%), 광선(+20%p)이 후반 "방어 센 애들" 해법이 된다 [원작 영상: "카카루(방무)가 사기급"].
- **원본이 비정상인 행**(방어 255 또는 HP 100)은 인접 라운드에서 보정: r23 스커지 2500/12 + 속도 x1.7, r25 하이브 20000/20, r29 아칸 7000/24, r30 넥서스 40000/30, r33 베슬 10000/30, r38 에그 16500/36 + 속도 x0.7, r43 아비터 35000/42, r48 우르사돈 65000/52. 전체 50행 결과는 `이식설계_데이터.md` ROUNDS.
- 전체 표는 데이터 문서. 대표값(게임 HP): r1 28, r5(보스) 420, r10(보스) 1,080, r20(보스) 3,360, r30(보스) 10,790, r40(보스) 21,950, r49 18,150, r50(보스) 286,440.

**시뮬 결과** (유체 모델: 매 라운드 전부 뽑기→3기 자동합성, 배치 효율 E=0.4; 코드 `docs/이식설계_밸런스시뮬.js`)

| 정책 | 10%ile 패배 라운드 | 중앙값 | 90%ile | 완주율 |
|---|---|---|---|---|
| 뽑기+자동합성만 | 14 | 34 | 48 | 6% |
| + 8라운드부터 무작정 강화 | 13 | 28 | 49 | 9% |
| + 강화 + 히어로 강화 3레벨 | 18 | 39 | 51 | 23% |

해석: 평균 도전은 약 r34(x1 기준 13.5분)에서 끝나고, 운과 운영이 좋으면 완주. 원작 영상(5판 중 완주 0, 4판이 r11~39 패배)과 비슷한 난이도. 강화/배치 최적화가 더 잘 되는 실제 유저는 위 표보다 위. **출시 전 `HP_K`(±20%)만 돌려 튜닝**하면 된다. 초반(r1~5)은 mob 평균 8~11기로 완만.

| 항목 | 원작 | 이식 |

### A9. 난수 (일일 챌린지 결정론) [신규]

- `seed = parseInt(YYYYMMDD)`. 스트림 4개를 분리: `rng.hero = mulberry32(seed)`, `rng.gacha = mulberry32(seed ^ 0xA5A5A5A5)`, `rng.merge = mulberry32(seed ^ 0x5A5A5A5A)`, `rng.misc = mulberry32(seed ^ 0x3C3C3C3C)`(처치 도박/라운드 히든).
- 뽑기 n번째 결과는 모두에게 같다. 합성 m번째 결과도 같다 → 랭킹은 **운이 아니라 운영**(언제 합성/강화/판매하는가)으로 갈린다. 연습 모드는 `Math.random` 시드.
- 외형용 난수(몹 색 흔들림, 파티클)는 `Math.random` 허용(시뮬 결과에 영향 없음).
- 시뮬레이션은 고정 dt(1/60). `Math.random()`/`Date.now()` 를 시뮬 로직에서 쓰지 않는다.

## B. 캐릭터 32종 (4무리 x 8등급)

무리 역할: 🌿숲=단일 고화력(x1.10), 🔥불꽃=광역+화상(x1.0), 🌊물결=둔화+연쇄(x0.9), ✨별빛=방어 무시(방무 등급별 0/0/5/10/20/30/50/100%)(x0.95).
이름은 동물→신화로 갈수록 웅장(패런츠는 `§...§` 표기 [원작], 4종 모두 "첫 말랑" 신들).
수치 곡선: 등급당 기준 DPS `5 / 17 / 60 / 210 / 760 / 2700 / 9500 / 40000` (약 x3.5). 3기 합성(3x)보다 다음 등급이 약간 높아 합성이 소폭 이득이되, 운(무리 랜덤)을 건다. 사거리는 130→240(+타입 보정). 공격력/회 = 기준DPS x 무리배율 x 타입배율 x 쿨다운. 전 표 [신규].

## G. 랭킹 점수식, 시즌, 부정 방지

```
score = 100 * 도달라운드(R) + 처치수 + floor( min(유닛점수 합 U, 20000) * 0.5 ) + (승리 ? 3000 + 20 * 최종보스 남은초 : 0)
```
- U = 종료 시점 필드 유닛 점수 합(등급별 1/3/9/27/81/243/729/2187 x 스택). 최대 이론치 약 20k. (기존 식 `wave*100 + kills*2` 대체)
- **일일 챌린지**: 하루 시드의 히어로+가챠 결정론. 하루 N회 재도전 가능, 랭킹은 최고점만. 탭: 오늘 / 시즌 / 전체. 연습 모드(무작위 시드)는 로컬 최고점만.
- **시즌**: 4주(월요일 시작). 시즌 점수 = 그 기간 일일 최고점 상위 7일 합(히어로가 매일 달라 공정).
- DB 컬럼 추가: `mode text, seed int, win bool, units int, ver text, inputs text(nullable)`. RLS `check (score between 0 and 30000 and wave between 0 and 50)`.
- 부정 방지(단계적): ① 서버 범위 검사(점수 <= 100*R + 처치 상한 + 20000 + 4200) ② 클라이언트가 입력 로그 `[frame, op, arg]`(뽑기/합성/강화/판매/선택권, 압축 base64)를 함께 전송 ③ 2단계: Edge Function 이 로직 모듈(`data.js` + 시뮬 코어)을 헤드리스로 재생해 점수 일치 검증(이를 위해 game.js 는 **시뮬 로직과 FX 호출을 분리**하고 FX 는 `HEADLESS` 시 no-op) ④ 닉네임 길이/금칙어, 레이트리밋.

## J. 무리 4타입과 공업(공격력 업그레이드) 시스템 (원작 핵심 재미)

원작의 전략 축: **어떤 종족을 뽑느냐(운)에 따라 어느 공업에 투자할지 결정**하고, 후반엔 합성보다 공업 몰빵이 낫다. 우리 이식에서도 4무리 = 원작 4타입(테란/저그/프로토스/기타)에 1:1 대응하며, 공업은 무리별 독립 트랙이다.

### J1. 원작 근거 (확정/추정/미확인)
| 항목 | 내용 | 상태 |
|---|---|---|
| 종족 라벨 4종 | 테란/저그/프로토스/기타(혼종·크리터·아칸 등). 유닛 패널에 종족 표기, 영웅 보너스는 종족 단위 | 확정 (영상 99행, 맵 208행) |
| 종족별 공격 업그레이드 | 종족별 공업 레벨이 존재. 직접 구매 버튼 "공격력 업그레이드" 존재(id123). 레벨은 히어로·시너지·보스 보상으로도 증가 | 확정(버튼 존재) / 보스 보상은 추정 |
| 업그레이드 비용·최대 단계·증가율 | 화면/문자열에 없음. 버튼의 "광물100/가스50"은 가격표 재활용 가능성 | **미확인** -> 우리 값 [신규] |
| 업그레이드 입력 방식 | 'Select' 유닛이 구역을 다니며 구입(추정) | 추정 |
| 영웅 공업 보너스 | 아르타니스 프로토스 +3(시작+30), 다고스 저그 +3, 아크튜러스 테란 +3, 피닉스 프로토스 +4, 오버마인드 저그 +5(영상 7업/현실), 젤나가 기타 +4, 아몬 전체 +2(영상 4업/시작 +50~60) | 확정 |
| 종족 시너지 | 같은 종족 히어로 3명 -> 그 종족 공업 +2, 4명 -> +2 및 전원 +50 | 확정 |
| 혼종 합성 | 저그1+프로토스1(같은 등급, 히든 이하) -> 같은 등급 기타 1기 | 확정(문자열) |
| 합성 유닛과 공업 | 상위 합성 결과가 공업 약한 종족이면 오히려 약해짐(80:00), 에픽도 공업 잘된 하위에 못 이김(47:00), 후반 몰빵(102:00) | 확정(발언) |
| 4종/등급이 종족별 1종인지 | 맵 분석은 "각 등급 4종"만 확정, 종족 배분 불명 | 미확인 -> **1무리 1종**으로 결정(아래) |

### J2. 4무리 = 4타입 구성 (결정)
- 등급마다 4종 = 무리당 정확히 1종 (`idx = grade*4 + clan`). 뽑기에서 등급이 정해지면 4종이 같은 확률이므로 **무리는 25%씩 균등 운빨**. 보유 무리 분포가 곧 공업 투자처(편중 시 한 무리에 몰빵).
- 무리별 특성 (A, B장): 숲 단일 고화력, 불꽃 광역+화상, 물결 둔화+연쇄, 별빛 방무. **공업 가치가 무리마다 다름**: 불꽃/물결은 유닛 수가 많을수록 유리(광역), 숲/별빛은 소수 정예 몰빵 유리.
- 혼종(원작 '기타') 대응: 4번째 무리 별빛 = '기타'. 혼종 합성 레시피는 **삭제** (히어로 혼종 대체: 아래 J6 "무리 혼합 히어로" 선택 구현).

### J3. 공업 트랙 4개 (무리별 독립)
| 항목 | 값 [신규] |
|---|---|
| 레벨 | 무리별 `bought`(구매) + 히어로/시너지/보스 보너스 `bonus`. 표시 Lv = bought + bonus |
| 구매 비용 | `cost(bought) = 60 + 10*bought` 미네랄 (0->1: 60, 10->11: 160, 24->25: 300, 25 도달 총 4500). **무리별 독립 가격** (한 무리만 올려도 다른 무리 비용 불변) |
| 최대 구매 | 25단계. bonus 는 별도 가산하되 표시 Lv 상한 35 |
| 효과 | 해당 무리 모든 유닛 피해 `x (1 + 0.12 * Lv)` (선형, 가산). Lv 10 = x2.2, Lv 25 = x4.0, Lv 35 = x5.2 |
| 적용 범위 | 이미 필드에 있는 유닛과 이후 합성 결과 유닛 모두 즉시 적용(무리는 유닛 정체성이므로). 히어로 유닛도 자기 무리 고정이 아니라 **히어로 전용 트랙 없음** = 전 무리 최고 Lv 의 50% 적용 |
| 방어(방업) | 원작 몹은 방어력 표가 있으나 플레이어 방업은 미확인 -> **없음** (유닛 방어 개념 없음) |
| 전략 균형 | 합성: 3기 -> 다음 등급(~3.5배 화력, 가격 3배) 이득 소폭. 공업: 60~300 미네랄에 +12%p. 초반 유닛 적을 땐 합성, 후반 유닛 화력이 몰린 무리에 공업이 효율 우수. **교차점**: 한 무리 화력 비중 55% 이상이면 공업이 합성보다 낫도록 계수 설계(시뮬 `이식설계_밸런스시뮬.js` 의 up 정책으로 검증, 튜닝 `CONST.UP_STEP=0.12`, `UP_COST0=60`, `UP_COSTK=10`) |
| 보스 보상 | 챕터 보스(r10/20/30/40) 처치 시 **공업 선택권 1회**(원하는 무리 +1 보너스 레벨 무료). 기존 등급 선택권과 별개 모달. (원작 '보스 보상으로 증가' 추정에 대응, 신규) |
| 이미 쓴 문서 불일치 정리 | A장의 "무리 공업" 표기와 동일. 위 수치가 우선 |

### J4. 공업 UI/UX
- 하단 버튼 `⬆ 강화` -> 시트: 4행(무리 엠블렘, 이름, `Lv n (+보너스)`, 현재 배율 `x2.2`, 다음 비용/증가 `+12%`, 보유 유닛 점수 비율 막대 "화력 비중 61%", [강화]). 비중 막대가 "어디에 투자할지" 판단 도구.
- 뽑기 직후 토스트에 해당 무리 Lv 표시 (예: `불꽃 Lv6`). 선택 유닛 카드에 `숲 공업 Lv4 (x1.48)` 줄.
- HUD 상단 우측에 4무리 미니 Lv 칩(엠블렘+숫자) 상시 표시, 구입 가능하면 맥동. 보스 공업 선택권 보유 시 칩 점멸.
- 합성 경고 변형: 공업 낮은 무리의 상위 유닛이 나올 수 있음을 합성 확인 문구에 표기 ("무리는 랜덤, 현재 공업 Lv: 숲4 불꽃1 물결0 별2").
- 후반 몰빵 안내 없음(발견 요소), 대신 확률표 모달에 "무리별 25%" 설명.

### J5. 무리 시너지 (원작 '히어로 종족 시너지' 단순화)
1인 플레이라 히어로 3~4명 규칙은 불가 -> **무리 공명**으로 대체 [신규]: 필드에 같은 무리 유닛이 **서로 다른 등급 4종 이상** 있으면 그 무리 공업 보너스 +2, **6종 이상**이면 +4 (재계산형, 유닛 팔면 사라짐). 합성/판매와 전략적 긴장, 진행 칩 UI("숲 공명 3/4종"). 전원 +50 미네랄은 삭제(대신 첫 달성 시 +50 1회/무리).

### J6. 히어로와 공업 연동 (D장 보완)
D장 히어로 10종 중 공업 관련: 다람이(숲 +3), 화랑이(불꽃 +5), 첫 말랑(전 무리 +2, 시작 +50). 추가 후보(구현 여력 시, 확률은 합 100 유지하도록 럭키/점쟁이에서 각 1%p 차감해 배분):
- 물결 대장 `파랑이` 4%: 물결 +4. 별빛 대장 `반짝 가이드` 3%: 별빛 +4, 시작 +10. (원작 젤나가 기타 +4 대응)
- 무리 혼합 히어로(원작 혼종): `얼룩이` 선택 구현: 서로 다른 무리의 같은 등급(히든 이하) 2기 -> 그 등급 임의 유닛 1기 (합성 버튼 별도 '혼합'). 구현 비용 크면 생략.
- 아몬 시작 공업: `첫 말랑` = 전 무리 bonus +2(원작 아몬 +2 / 영상 4업은 협동 합산) 확정 반영.

### J7. 타입(무리) 즉시 식별 비주얼 (등급 언어와 충돌 방지)
충돌 원인: 등급색(초록 파랑 보라...)과 무리색이 겹침. 해결 = **채널 분리**:
| 채널 | 무리(종류) | 등급(레벨) |
|---|---|---|
| 색 | 몸 색상 팔레트 + 엠블렘 색 (숲 #4caf50계 녹/갈, 불꽃 #ff5a36계 적/주황, 물결 #29b6f6계 청록/하늘, 별빛 #ffd54f+#b388ff 노랑/라벤더) | 테두리, 오라, 뱃지, 받침 색 |
| 모양 | **엠블렘 아이콘**: 잎 / 불꽃 / 물방울 / 별 (타일 좌하단 12px, 항상 같은 위치, 흰 외곽) | 뱃지: 점/별/보석/왕관 + 개수 |
| 위치 | 좌하단 | 우상단(뱃지), 테두리 |
| 크기/장식 | 변하지 않음 | 크기 배율, 장식 수 |
- 규칙: 등급색을 쓰는 UI(테두리, 오라, 뱃지)는 몸 색을 따라가지 않고, 몸 색상은 무리 팔레트 안에서만 고른다. 유니크(보라)와 별빛(라벤더) 충돌은 별빛 몸색을 노랑 위주로 하고 라벤더는 보조로만 사용, 엠블렘 모양으로 보증.
- 타일 하단 3px 색 띠(무리색) 추가. 그레이스케일에서도 엠블렘 모양 + 뱃지 모양으로 구분 가능해야 함.
- 선택 유닛 카드/확률표에도 엠블렘 표시. 갤러리 `?gallery=1` 은 4무리 x 8등급 격자로 검증.

### J8. 데이터 스키마/구현 분할 반영
- `CLANS[c]`: `{key,name,emblem:"leaf|flame|drop|star",color,tile,role}` (타입 필드). `CHARS[i].clan = i%4`, `CHARS[i].grade = i>>2`.
- `CONST`: `UP_STEP:0.12, UP_COST0:60, UP_COSTK:10, UP_MAX:25, UP_LV_CAP:35, BOSS_UP:[10,20,30,40], RESONANCE:{4:2,6:4}, RESONANCE_FIRST:50`.
- S 추가: `S.up=[{bought,bonus}x4]` (기존 숫자 4개 -> 객체), `S.upTickets:number`, `S.resonance:[n,n,n,n]`.
- data.js 순수 함수: `upgradeCost(bought)`, `dmgMul(lv)`, `clanLevel(S,c)`, `resonanceBonus(slots,c)`, `clanPower(slots)` (비중 막대용).
- game.js API: `GAME.upgrade(clan)`, `GAME.useUpTicket(clan)`; ui.js: `uiUpTicket()`, 강화 시트; graphics.js: `drawEmblem(c,clan,x,y,size)`, `drawClanBar`, `drawSlotTile` 에 clan 인자 추가. 소유권은 H1 그대로.

## 부록 K. 공업 원작값 반영 (docs/공업_원작분석.md)
- J1/J3 의 임시값(60+10×횟수, +12%)은 폐기. 확정: 비용 `25 + 5×횟수`(원작 25+5×(N-1)), 단계당 효과 +35% 가산(`CONST.UP_STEP`). 효과는 원작이 유닛별로 +100%~고정값이라 추정 환산.
- 최대 단계 UP_MAX 25 / 표시 Lv 상한 35 는 유지(원작은 사실상 무제한).
- 밸런스: 봇 시뮬(HP_MUL 1→59%, 1.5→18%, 2→6%, 4→0% 완주). `CONST.HP_MUL=1.5` 채택. 사람은 봇보다 약하므로 실제 완주율은 더 낮을 것 — 출시 후 조정.
